# AI Assistant for STE Slicer

Каркас плагина для аддитивного трека хакатона 2026. Цель: запрос пользователя и модель -> настройки STE Slicer -> проект 3MF, G-code и объяснение решений.

Правила разработки и ограничения для работы агентов: [AGENTS.md](AGENTS.md). За нашей работой закреплена роль №1 — интеграция STE Slicer; остальные роли уточняются. [План нашей части](docs/PLAN_SLICER.md), [принятое ТЗ 01](docs/tasks/TASK_01_SLICER_SETTINGS.md), [принятое ТЗ 02](docs/tasks/TASK_02_STATE_AND_MODES.md), [ТЗ 03 на ручной приёмке](docs/tasks/TASK_03_PROFILES_AND_MATERIALS.md) и [следующее ТЗ 04](docs/tasks/TASK_04_MODEL_LOADING.md).

**Реализовано:** пункт меню плагина, локальный HTTP-сервер, SPA с историей текущего диалога и демонстрационным ответом, минимальный MCP с чтением/изменением глобального `layer_height`, диагностикой машины, переключением трёх режимов, списками и выбором встроенного качества/материалов через Qt. LLM, вложения, создание/сохранение профилей, остальные настройки, модели, слайсинг и экспорт пока не реализованы.

Проверено: синтаксис Python с грамматикой 3.5, JavaScript через `node --check`, HTTP/MCP и 72 автоматические проверки на Python 3.13. В настоящем **STE Slicer 7.10.12**, **Stereotech Hybrid 530 V5.2.4** приняты изменение/восстановление layer_height и режимы 3D/5D Spiral/5D с проверкой реальных backend и UI. Протоколы: [ТЗ 01](docs/reports/TASK_01_RUNTIME.md), [ТЗ 02](docs/reports/TASK_02_RUNTIME.md). **ТЗ 03 прошло ревью и автоматические проверки, ручной прогон качества/материалов ещё не выполнен**: [ревью](docs/reports/TASK_03_REVIEW.md). Слайсинг, экспорт и shutdown реального приложения этой приёмкой не покрыты.

## Быстрый запуск без слайсера

Нужен Python 3.5+; сторонние пакеты для демонстрационного сервера не нужны:

```powershell
python scripts/dev_server.py
```

Откройте адрес, напечатанный в терминале. Остановить сервер: Ctrl+C. Порт выбирается автоматически; сервер слушает только `127.0.0.1`.

## Проверки разработки

Из корня репозитория, на отдельном современном Python (проверено на 3.13):

```powershell
python -m unittest discover -s tests -v
git diff --check
```

Сторонние пакеты не нужны. Две проверки используют временный HTTP-сервер на 127.0.0.1; среда должна разрешать loopback. Проверка синтаксиса с грамматикой 3.5 выполняется современным парсером. Runtime-код плагина остаётся совместимым с Python 3.5, а тестовый runner не обязан запускаться внутри слайсера.

Изолированные тесты не заменяют приёмку в приложении. Шаги ручной проверки и команды MCP приведены в [plugin/README.md](plugin/README.md), результаты выполненного прогона — в [протоколе](docs/reports/TASK_01_RUNTIME.md).

## Репозиторий и совместная работа

Репозиторий команды: [Aintrex/mosprom2026](https://github.com/Aintrex/mosprom2026). Клонировать весь STE Slicer для разработки отдельного плагина не нужно. Его исходники и встроенные плагины используются как справочник API; нужна версия организаторов, особенно для 5D.

Для нового участника:

```powershell
git clone https://github.com/Aintrex/mosprom2026.git
Set-Location mosprom2026
```

Работайте в отдельных ветках, например `codex/slicer` и `codex/web`. Изменения общих контрактов согласовывайте перед интеграцией. Несколько чатов в одной папке видят одни и те же файлы; runtime-код нашей роли одновременно меняет один исполнитель. Commit/push от агента выполняются только по прямому запросу пользователя с настроенной в Git авторской идентичностью.

Исходники плагина находятся в `plugin/AIAssistant/`. Установленная копия в AppData обновляется отдельно от GitHub; подробности — в [контракте](docs/API_CONTRACT.md#8-исходники-git-и-установленная-копия). Ключ LLM, дистрибутивы, лицензии и временные материалы в Git не добавлять.
