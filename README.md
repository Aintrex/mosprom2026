# AI Assistant for STE Slicer

Плагин для подготовки 3D-печати в STE Slicer с помощью диалогового AI-ассистента. Проект разрабатывается для аддитивного трека хакатона 2026.

Целевой сценарий: запрос и вложения → выбор настроек, профиля, материала и режима печати → работа с моделью → слайсинг → проект 3MF, G-code и объяснение выбранных параметров. G-code должен формироваться движком слайсера.

## Текущие возможности

Проект находится в разработке. Реализованы:

- запуск плагина из меню расширений и открытие чата в системном браузере;
- локальный HTTP-сервер и SPA на HTML/CSS/JavaScript без frontend-сборки;
- MCP через JSON-RPC: `initialize`, `tools/list`, `tools/call`;
- чтение и изменение глобального `layer_height` с подтверждением фактического значения;
- диагностика активной машины и backend, переключение режимов `classic`, `cylindrical`, `cylindrical_full`;
- список и выбор встроенных профилей качества и материалов;
- импорт локальных STL/OBJ/3MF, список объектов сцены, их ID и мировые габариты.

Инструменты слайсера доступны через `/mcp`. Чат пока возвращает демонстрационный ответ: LLM и вызов инструментов из диалога не подключены. Локальный импорт модели через MCP не является загрузкой вложений из браузера.

Предстоит реализовать интеграцию OpenAI-совместимого Chat Completions с tool calling, вложения JPG/PNG и моделей в чате, расширенные настройки и преобразования объектов, создание и сохранение профилей, слайсинг с прогрессом, экспорт G-code и сохранение 3MF.

## Совместимость

- STE Slicer с форматом плагинов Cura 3.6, `api: 5`.
- Python 3.5; PyQt5 и `UM` предоставляются слайсером.
- Основная конфигурация проверки: **STE Slicer 7.10.12**, **Stereotech Hybrid 530 V5.2.4**.

Обращения к API приложения из HTTP-потока передаются в основной Qt-поток через `app.callLater(...)`. Сервер слушает только `127.0.0.1`. Для MCP и будущего LLM используется единый реестр инструментов с проверкой аргументов.

## Установка

1. Установите сборку STE Slicer, выданную для хакатона.
2. В слайсере откройте **Справка → Показать папку конфигурации**.
3. Сохраните проект и закройте приложение.
4. Скопируйте каталог `plugin/AIAssistant` в каталог `plugins` папки конфигурации.
5. Перезапустите слайсер и выберите **AI Assistant → Open chat** в меню расширений.

Подробные инструкции и примеры вызовов MCP: [руководство плагина](plugin/README.md). При обновлении исходников установленную копию плагина нужно обновить отдельно.

## Запуск интерфейса без слайсера

Из корня репозитория:

```powershell
python scripts/dev_server.py
```

Требуется Python 3.5 или новее, сторонние пакеты не нужны. Откройте адрес из терминала; порт выбирается автоматически. Остановка — `Ctrl+C`.

Этот режим позволяет проверить интерфейс и HTTP/MCP. Операции с приложением возвращают `slicer_not_connected`.

## Структура проекта

```text
plugin/
  README.md               # установка и ручные проверки
  AIAssistant/
    plugin.json           # метаданные плагина, API 5
    AIAssistant.py        # жизненный цикл Extension, меню и сервер
    server.py             # HTTP, SPA и JSON-RPC
    agent/                # реестр инструментов, MCP и каркас LLM
    slicer/               # адаптер STE Slicer и мост в Qt-поток
    web/                  # HTML, CSS и JavaScript
docs/                     # требования, архитектура, контракты и отчёты
scripts/dev_server.py     # запуск без STE Slicer
tests/                    # изолированные проверки
results/                  # результаты обработки моделей
```

## Проверки и ограничения

Команды для разработки на отдельном современном Python:

```powershell
python -m unittest discover -s tests -v
git diff --check
```

По [отчёту об импорте моделей](docs/reports/TASK_04_REPORT.md), выполнены 94 автоматические проверки на Python 3.13.6 и проверка синтаксиса с грамматикой Python 3.5. Изолированные тесты используют подмены API и не заменяют запуск в STE Slicer.

В STE Slicer 7.10.12 с профилем Stereotech Hybrid 530 V5.2.4 подтверждены чтение, изменение и восстановление `layer_height`, а также переключение трёх режимов с проверкой UI и фактического backend. Протоколы: [настройки](docs/reports/TASK_01_RUNTIME.md), [режимы](docs/reports/TASK_02_RUNTIME.md).

Выбор качества и материалов, а также импорт моделей требуют отдельной ручной приёмки в слайсере. Полный сценарий через LLM, слайсинг, экспорт и повторное открытие сохранённого 3MF пока не подтверждены. Готовых результатов обработки моделей в `results/` нет.
