# AI Assistant for STE Slicer

Плагин для подготовки 3D-печати в STE Slicer с помощью диалогового AI-ассистента. Проект разрабатывается для аддитивного трека хакатона 2026.

Целевой сценарий: запрос и вложения → выбор настроек, профиля, материала и режима печати → работа с моделью → слайсинг → проект 3MF, G-code и объяснение выбранных параметров. G-code должен формироваться движком слайсера.

## Текущие возможности

Проект находится в разработке. Реализованы:

- запуск плагина из меню расширений и открытие чата в системном браузере;
- локальный HTTP-сервер и SPA на HTML/CSS/JavaScript без frontend-сборки;
- POST `/api/files`: ограниченная загрузка JPG/PNG/STL/OBJ/3MF в приватное временное хранилище с file_id (роли 2A/2B; выбор файла в чате, image_url для фото, load_model_file через прежний native-адаптер; ручная приёмка открыта);
- GET `/api/files/{file_id}`: скачивание подтверждённого актуального native-экспорта из карточки чата (роль2C; отдельный download-ID, поток до64KiB, dev=false; ручная приёмка открыта);
- Chat Completions с tool calling через существующий реестр, Qt-настройки URL/модели/ключа в Preferences, асинхронные sessions/messages/events и восстановление диалога (проверено с подменами, native-приёмка открыта);
- локальный архив нескольких диалогов: список/новый/открытие/удаление, сохранение подтверждённых версий JSON и отдельный безопасный текстовый контекст после перезапуска (2G, до20 чатов/100 архивных сообщений/512КиБ на чат/10МиБ суммарно; проверено на временном каталоге, STE-приёмка открыта);
- MCP через JSON-RPC: `initialize`, `tools/list`, `tools/call`;
- каталог 120 параметров в 10 группах: адресное описание по ключам/категории/поиску с пагинацией, чтение и изменение доступных глобальных и явно выбранных экструдерных настроек с подтверждением фактического значения (ТЗ 13, native-приёмка открыта);
- диагностика активной машины и backend, переключение режимов `classic`, `cylindrical`, `cylindrical_full`;
- список и выбор встроенных профилей качества и материалов; создание/выбор/сохранение custom-профилей с подтверждением контейнеров и файлов (ТЗ12, native-рестарт не проверен);
- импорт локальных STL/OBJ/3MF, список объектов сцены, их ID и мировые габариты;
- чтение мировой матрицы/origin, перемещение, поворот, масштабирование и удаление верхней модели/группы штатными UM-операциями с Undo (ТЗ 08, ожидает native-приёмки);
- штатная расстановка classic через ArrangeObjectsJob с собственным ID/статусом и фактическими after (ТЗ 09, native-приёмка открыта; полного размещения без явного выхода за границы job не подтверждает);
- запуск штатной classic/cylindrical/cylindrical_full-нарезки, ID, статус/прогресс и чтение времени/материала из STE Slicer (ожидает runtime-приёмки);
- асинхронный экспорт G-code и проекта 3MF через штатные writers с проверкой актуальности нарезки (ожидает runtime-приёмки).

Инструменты доступны через `/mcp` и новый чат; диагностический load_model(path) исключён из LLM; приложенную модель агент импортирует через load_model_file по доверенному file_id. Legacy `/api/message` сохранён отдельно как демо. Роль2D автоматически читает прогресс/результат подтверждённых собственных запусков агента после idle/лимита LLM, без новых запросов провайдеру/автозапуска операций. Прямой MCP/ручные UI-запуски автоматически не наблюдаются; завершение ответа агента не завершает engine. Локальный импорт через MCP не является загрузкой вложений из браузера.

Предстоит проверить агентную интеграцию, преобразования и расстановку в STE, вложения JPG/PNG и моделей в чате с реальным провайдером/native-reader, custom-профили и HTTP-скачивание артефактов в STE; все три режима нарезки требуют native-приёмки.

## Совместимость

- STE Slicer с форматом плагинов Cura 3.6, `api: 5`.
- Python 3.5; PyQt5 и `UM` предоставляются слайсером.
- Основная конфигурация проверки: **STE Slicer 7.10.12**, **Stereotech Hybrid 530 V5.2.4**.

Обращения к API приложения из HTTP-потока передаются в основной Qt-поток через `app.callLater(...)`. Сервер слушает только `127.0.0.1`. Для MCP и LLM используется единый реестр инструментов с проверкой аргументов.

## Установка

1. Установите сборку STE Slicer, выданную для хакатона.
2. В слайсере откройте **Справка → Показать папку конфигурации**.
3. Сохраните проект и закройте приложение.
4. Скопируйте каталог `plugin/AIAssistant` в каталог `plugins` папки конфигурации.
5. Перезапустите слайсер и выберите **AI Assistant → Open chat** в меню расширений.

Подробные инструкции и примеры вызовов MCP: [руководство плагина](plugin/README.md). При обновлении исходников установленную копию плагина нужно обновить отдельно.

## Запуск интерфейса без слайсера

Из корня репозитория:

```powershell
python scripts/dev_server.py
```

Требуется Python 3.5 или новее, сторонние пакеты не нужны. Откройте адрес из терминала; порт выбирается автоматически. Остановка — `Ctrl+C`.

Этот режим позволяет проверить интерфейс и HTTP/MCP. Операции с приложением возвращают `slicer_not_connected`.

## Проверки и ограничения

Локальное исправление аргументов после0b67564 связывает key/value в схеме и добавляет только для LLM явный ограниченный разбор числовой строки set_setting с уведомлением. Прямой MCP остаётся строгим; бесконечные повторы одинаковых неверных аргументов прекращаются. Ошибки преобразования различают preflight/dispatch/unknown; реальная причина пользовательского отказа поворота без его payload не установлена.
