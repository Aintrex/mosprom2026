# Актуальная приёмка опубликованной версии

Назначить существующему «Разрабу» после публикации ведущим. Это подготовка реальной приёмки, без новой функциональности.

Создать `docs/CURRENT_VERSION_ACCEPTANCE.md`: короткая последовательная инструкция для пользователя именно текущего canonical-плагина. Старые `TESTING_STEP_BY_STEP.md`, helper и frozen296 не менять. Команды и схемы сверить с текущим реестром/API, PowerShell разобрать Parser без исполнения. Указать фактический SHA публикации, различать скачанную и установленную копии.

Включить: настройка соединения с текущим портом; чтение машины и адресного describe (keys/category/query/page) из каталога120 без выгрузки всех страниц; одна допустимая запись/readback/восстановление с учётом global/extruder; два учебных чата с разными фактами → Saved → переключение → обычный restart → отдельное продолжение → истёкшие вложения → удаление тестового диалога с подтверждением и повторный restart. Для каждого шага дать точный ожидаемый результат и признаки отказа. Перед любой записью сохранять исходное значение, после неизвестного исхода только читать, не повторять запись автоматически.

Сослаться на существующую native-приёмку профилей/сцены/трёх режимов/engine/writers/Preview/reopen, без копирования огромного сценария. Добавить таблицу «не проверено / результат пользователя / безопасная ошибка», не заполнять успехи заранее. Подготовить несколько коротких пользовательских промптов, отделив теорию от операций. Напомнить про общую сцену и отсутствие живых старых ID/файлов в памяти чатов.

Не запускать STE/LLM/MCP и не устанавливать AppData; не читать ключи, не менять runtime/договорённые лимиты, не делать Git-мутаций/публикации, не трогать Word/презентацию. После документа и краткого отчёта остановиться для ревью. Если обнаружена фактическая несогласованность API или дефект, сообщить ведущему с воспроизводимым сценарием до расширения задачи.
