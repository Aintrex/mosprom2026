# ТЗ12: пользовательские профили качества

Статус: назначается ведущим24.10 после приёмки11 в исходниках (275 Python+8 JS). Выполнить только этот этап, предварительно подтвердив source-схему ниже; предыдущие этапы сохраняются.

## Результат

Через единый MCP/LLM-реестр можно создать пользовательский профиль из текущих настроек, найти и выбрать его, изменить разрешённую настройку и сохранить изменения в этом профиле штатным API STE Slicer. Сохранение подтверждается контейнерами и штатным механизмом хранения, а не сообщением «готово» по одному возврату void/bool.

Без нового UI, скачивания файлов, переименования/удаления/импорта профилей, клонирования материалов или расширения allowlist. Встроенные профили не перезаписывать. Native-проверку в приложении отделять от изолированных тестов.

## Сначала подтвердить исходники

- `steslicer/Machines/QualityManager.py`: `getQualityChangesGroups`, `createQualityChanges`, `_createQualityChanges`. Создание копирует прежние qualityChanges и userChanges, затем очищает userChanges. Возврат None не подтверждает ни создание всех контейнеров, ни выбор нового профиля.
- `steslicer/Settings/MachineManager.py`: `setQualityChangesGroup(..., no_dialog=True)` и сигналы/контейнеры активного профиля.
- `steslicer/Settings/ContainerManager.py`: `updateQualityChanges()`. Возврат True сам по себе недостаточен: цикл может пропустить read-only/отсутствующий контейнер.
- `resources/qml/Preferences/ProfilesPage.qml`: штатный UI после create ждёт обновления модели и отдельно выбирает созданную группу. Не полагаться на её автоматическую активацию.
- Uranium `UM/Settings/ContainerRegistry.py` и `plugins/LocalContainerProvider/LocalContainerProvider.py`: штатное сохранение, фактические признаки ошибки/успеха и dirty-флаг. Не сохранять профили собственным ini/json-писателем, не запускать глобальный save всех Preferences ради одной операции.

До реализации кратко сообщить ведущему, как подтверждаются новая группа, перенос overrides, выбор и сохранение. Не добавлять большой универсальный механизм транзакций/отката.

## Минимальный контракт

Предпочтительно четыре отдельных инструмента без изменения старых обязательных аргументов:

- `list_custom_profiles {}`: стабильный ID глобального quality_changes контейнера, имя, quality_type, доступность, активность; при необходимости ID контейнеров экструдеров. Имя не использовать вместо ID для произвольного поиска в Registry.
- `create_custom_profile {name}`: штатный Create из текущего качества и overrides, выбор именно новой группы, readback. Непустое ограниченное имя; коллизию обрабатывать явно, возвращать фактические имя/ID. Не перезаписывать существующий профиль. Доказуемо сохранить значения прежнего custom и userChanges глобального/экструдерных стеков. Очистка userChanges допустима как штатный перенос в новый профиль и должна отражаться в ответе.
- `select_custom_profile {profile_id}`: только доступная группа текущей машины из актуального lookup; штатный выбор без диалога, readback global/extruder контейнеров. User overrides сохранять по прежнему правилу выбора профилей.
- `save_custom_profile {profile_id}`: только активная изменяемая пользовательская группа с этим ID. До мутации подтвердить все нужные контейнеры, затем штатный update, readback каждого перенесённого значения и очистки userChanges, штатное сохранение и подтверждение его результата. Указать, что проверено в памяти и на диске; не объявлять native restart-проверку выполненной.

Если source API требует другого небольшого контракта, согласовать до реализации. Все схемы в одном ToolRegistry; мутации помечены is_mutating, строгая валидация до Qt.

## Интеграция

Использовать прежние QtBridge, change_lock, профили/контейнеры и инвалидирование результата нарезки/экспорта. Чтение Registry/Preferences/stack и записи только в Qt-потоке. Сетевой/HTTP-поток не получает Qt-объекты. Занятые native-сцена/импорт/расстановка/слайсинг/экспорт и изменившийся контекст отклоняются до опасной записи. Новая машина, состав экструдеров, профиль или внешние настройки во время отложенного подтверждения должны дать явную ошибку.

Не применять автоматический rollback, удаляющий созданные native-контейнеры при частичном результате. Вернуть понятную ошибку и фактическое состояние; не повторять создание автоматически. Реальные пути хранения/ключи не выдавать браузеру. Прежние ограничения безопасного HTTP и Python3.5/api5 сохраняются.

## Проверки и отчёт

Проверить полезные сценарии: global+extruder overrides и прежний custom переносятся без потери; новое качество выбирается фактически; повторный save не создаёт дубликат; чужой/неактивный/read-only/неполный профиль отклоняется; silent skip/updateTrue и ошибка provider не становятся успехом; чужая смена контекста и busy-guard; старый slice становится неактуальным. Сохранить текущую регрессию11 и8 JS. Не писать тесты только ради количества.
