# ТЗ 09 — штатная авторасстановка

Подготовлено после ревью ТЗ 08 (197 тестов OK, native-приёмка открыта). Начать по отдельному сообщению ведущего. Работа в едином plugin/AIAssistant, без смены агента/SPA и без собственного упаковщика геометрии.

## Цель

Расставить верхние печатные модели/группы активной платформы штатным ArrangeObjectsJob, дождаться фактического завершения и вернуть реальные позиции/границы. Для первого объёма — classic. Успех запуска, завершение job и пригодность размещения различаются. Если часть моделей не поместилась, показать это, а не отвечать arranged:true.

## Что подтверждено по выданному форку

- SteSlicerApplication.arrangeAll (1192+) собирает selectable sliceable/group верхние объекты активной платформы. arrange(nodes,fixed_nodes) создаёт `steslicer.Arranging.ArrangeObjectsJob`, min_offset=max(buildVolume.getEdgeDisallowedSize()+2,8), вызывает start и не возвращает job. Одного app.arrangeAll недостаточно для корреляции завершения.
- Можно создать и удерживать тот же штатный ArrangeObjectsJob на Qt с теми же входами/правилом min_offset. Не подменять конструктор в дистрибутиве и не перехватывать чужие jobs.
- ArrangeObjectsJob.run вызывает штатные Arrange/ShapeArray, использует GroupedOperation/TranslateOperation, удаляет ZOffsetDecorator, размещает по X/Z и опускает на стол. Непоместившиеся модели переносит за пределы; ShapeArray.fromNode может пропустить модель без convex hull. getResult штатно остаётся None — это не самостоятельный признак ошибки.
- Job.run сам вызывает finished.emit, а UM.JobQueue после возврата ещё раз выставляет _running=false/_finished=true и посылает finished. Завершение принимать идемпотентно и только после публичных isFinished()==True и isRunning()==False; учесть hasError/getError. Первый ранний сигнал не освобождает guard.
- Job.progress в ArrangeObjectsJob не публикуется: обновляется только штатный Message. Процент плагина остаётся null, если достоверного источника нет; не вычислять свой прогресс по времени.
- ShapeArray.fromNode читает getConvexHull, при None/пустых точках возвращает None,None. На Qt проверить наличие допустимой hull до запуска, иначе понятный отказ вместо пропуска. Не заменять hull габаритным прямоугольником.
- BuildVolume.checkBoundsAndUpdate(node) и node.isOutsideBuildArea дают штатный признак. Он не является доказательством отсутствия всех пересечений/готовности к печати. Собственный физический валидатор не добавлять.

Уточнение при ревью черновика: fallback непоместившейся модели — x=200, z=-n*20 — может оказаться внутри широкого стола Hybrid 530. Значит, одних outside=false недостаточно даже для вывода о полном успехе native-поиска. Пока достоверный native-признак found_solution_for_all недоступен, all_fit оставлять null при всех inside и пояснять ограничение; outside=true позволяет false. Не выводить true из одних границ и не добавлять собственный упаковщик ради этого поля. Проверить случай fallback внутри широкого BuildVolume.

Читать также UM/Job.py, JobQueue.py, Signal.py, OperationStack.py и функции моделей/преобразований 08. Исходники только для чтения. Все собственные обращения к app/сцене/настройкам — Qt. Native job работает в штатной JobQueue как родной Arrange All; это документированная граница вызова native API, аналогично штатным writer jobs. Не добавлять собственные чтения сцены/самодельный алгоритм в worker и не запускать run на Qt.

## Контракт и выполнение

`arrange_models {}` запускает одну операцию и возвращает статус с непрозрачным arrangement_id. `get_arrangement_status {arrangement_id}` читает queued/running/completed/failed, progress:null либо достоверное значение, error, models с фактическим after и all_fit:true/false/null после проверки. Статус completed означает завершившийся native job; all_fit:false отдельно сообщает неподходящие объекты. Сохранять ID моделей и схему get_model_state/bounds из 08. Путь/имя файла не заменяют object_id.

Аргументы строгие, лишние поля/типы — -32602 до API. arrange_models входит в общий реестр и is_mutating; get_arrangement_status — чтение. Результат MCP/LLM прежний ok/data/error. Агентные снимки slice инвалидируются как при другой мутации, новый специальный UI не нужен.

До старта: активная машина/сцена/платформа, classic, отсутствие preview и конкурирующих импорта/нарезки/экспорта/преобразований. Для воспроизводимого первого объёма auto_slice выключается пользователем заранее; Preferences плагин не меняет. Выбрать все допустимые верхние модели активной платформы через существующий реестр; другие платформы и служебные узлы не затрагивать. Пустая сцена — понятный отказ/no-op с документированным ответом, без фиктивного job. Неподдерживаемые родители/hull/геометрия отклоняются до запуска; штатное пропускание слишком больших моделей не выдавать за размещение всех.

Сохранить ограничение ТЗ 08: automatic_drop_down и automatic_push_free должны быть подтверждённо false; иначе отказ до старта с инструкцией пользователю. Штатное опускание на стол внутри ArrangeObjectsJob допустимо, отдельная отложенная PlatformPhysics не должна менять результат после подтверждения. Проверить активную платформу всех печатных частей группы, а не только верхнего узла. Не менять настройки физики автоматически.

Создать собственный job/подписки на Qt и удержать общий guard до его окончательного выхода/проверки. В callback передать завершение через app.callLater, прочитать isFinished/isRunning/hasError, затем перечитать актуальную сцену, ID, transforms/bounds и outside. Подтвердить прежние машину/сцену/платформу/целевые модели и неизменность geometry/rotation/scale; перемещение и штатное удаление ZOffset учитывать как ожидаемые эффекты. Родные позиции/Undo не заменять локальным списком. Живые API-объекты из Qt не сериализовать в HTTP.

Принятый запуск имеет документированный конечный бюджет ожидания, без ожидания в Qt. Timeout не убивает и не отменяет уже работающий native job: failed не становится success по позднему сигналу, guard остаётся до фактического выхода. Никаких автоматических повторов/отката/kill. Предложить перечитать список/состояния, при зависшем native — перезапуск. Не закрывать живой контекст раньше job. Shutdown прекращает новые действия и безопасно снимает только допустимые подписки; API-неопределённость описать, не имитировать отмену.

Ручные параллельные изменения неподдерживаемы: при обнаруженном конфликте вернуть честную ошибку с фактическими сохранёнными изменениями. Результат/частичный результат инвалидирует старую нарезку и будущий экспорт. Не заявлять атомарный откат группы.

## Проверки и результат

Значимые сценарии: валидация до API, dev/no machine, пустая/другая платформа, группа/hull, собственный job/чужой сигнал, ранний и повторный finished, настоящий finished с ошибкой, getResult=None без ошибки, размещение всех/части, актуальные bounds и outside, сохранность остальных моделей/ID, общий guard, timeout/late finish/shutdown, stale slice, shared MCP/LLM registry. Подмены job/геометрии явно отделить от native; сохранить прежние тесты.

Native-сценарий после разрешённого обновления: 2–3 небольшие модели на classic, сохранить before, запустить и опрашивать свой ID, сверить фактическую расстановку и after, проверить штатный Undo и новый slice. Не выполнять принтер/LLM-запросы автоматически. API/README/PLAN и TASK_09_REPORT.md обновить точечно. Коммит/push/установка и последующие этапы не разрешены самим этим ТЗ; после отчёта остановиться для ревью.
