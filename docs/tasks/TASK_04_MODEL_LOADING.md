# ТЗ 04: загрузка моделей, список объектов и габариты

Статус: готово к передаче исполнителю. Это этап 03 плана нашей роли. ТЗ 01/02 приняты в STE Slicer; ТЗ 03 прошло ревью и 72 автоматические проверки, но ручная приёмка ещё открыта. Подготовка этого задания не закрывает её. Реализовать только текущий объём.

## Цель и границы

Через MCP загрузить локальные STL/OBJ/3MF в существующую сцену, дождаться фактического результата, получить адресуемые объекты и их размеры в миллиметрах. Возврат readLocalFile или ранний сигнал загрузки не считается успехом.

Прочитать AGENTS.md, docs/PLAN_SLICER.md, docs/API_CONTRACT.md, предыдущие задания и текущий код. Сначала git status; сохранить изменения других участников. Основной код — plugin/AIAssistant/slicer/, схемы — существующий agent/tools.py. Небольшой модуль models.py допустим; новые runtime-зависимости не нужны. Сохранить Python 3.5, Qt-мост и все действующие инструменты.

Не входят: поворот/перемещение/масштаб/удаление, отдельная авторасстановка, слайсинг, экспорт, LLM, frontend и HTTP-загрузка вложений. Штатное размещение/масштабирование при импорте не отключать скрытым изменением Preferences; возвращать фактическую геометрию после него. Модели организаторов и дистрибутив не добавлять в Git.

## Источники и особенности API

STE: <SOURCE_ROOT>/STE-Slicer-master; Uranium — соседний Uranium-steslicer. Это справочная копия для чтения, не путь в runtime-коде.

- steslicer/SteSlicerApplication.py: readLocalFile(QUrl, skip_project_file_check=False), _readMeshFinished, fileLoaded, fileCompleted, openProjectFile, checkIsValidProjectFile.
- В этой копии fileLoaded испускается **до** цикла добавления узлов; fileCompleted — после него. При пустом результате fileCompleted также возможен. При раннем выходе завершение может не прийти вообще. Нужны проверка сцены, привязка к своему файлу и конечное ожидание.
- readLocalFile по умолчанию может открыть диалог проекта для 3MF. Для этого задания нужен импорт моделей через подтверждённый mesh-путь с skip_project_file_check=True, без открытия workspace и замены машины/глобальных профилей. Проверить фактическое поведение установленной версии.
- plugins/3MFReader/ThreeMFReader.py: вложенные узлы, преобразования, единицы, декораторы и настройки отдельных объектов. Mesh-импорт не означает удаления object overrides; не обещать этого пользователю. Глобальное восстановление проекта и повторное открытие будущего экспортированного 3MF — отдельный этап.
- Uranium: UM/Mesh/ReadMeshJob.py, UM/FileHandler/ReadFileJob.py; собственный параллельный загрузчик вместо штатного не писать. Не воспроизводить его обращения к приложению из нашего worker.
- UM/Scene/Iterator/DepthFirstIterator.py, UM/Scene/SceneNode.py, UM/Scene/Scene.py: обход, getMeshData, getChildren, getBoundingBox, getWorldTransformation; scene.findObject использует Python id(node), отдельного подтверждённого node.getId здесь нет.
- UM/Math/AxisAlignedBox.py: minimum/maximum и размеры. Внутренние координаты Uranium: X/Z — плоскость стола, Y — вертикаль. Формат ответа ниже сохраняет эти оси явно.

Чтение сцены, узлов, Preferences, машины и подключение/отключение сигналов приложения выполнять в Qt-потоке через существующий мост. Наружу отдавать только JSON-данные. Чтение файлов и ожидание не переносить в Qt-поток; штатный readLocalFile сам запускает job.

## Инструменты и контракт

Реестр и schemas общие для MCP и будущего LLM. Структура, типы, обязательные и лишние поля валидируются до обращения к приложению.

| Инструмент | Аргументы | Назначение |
| --- | --- | --- |
| load_model | {"path":"C:/Models/bracket.stl"} | Импорт локального файла с подтверждением новых объектов |
| list_models | {} | Адресуемые объекты текущей сцены |
| get_model_bounds | {"object_id":"opaque-id"} | Актуальный мировой bounding box объекта |

path — временный диагностический вход для прямого MCP, пока нет upload API. Принимать только непустой абсолютный путь к существующему читаемому обычному локальному файлу с расширением .stl/.obj/.3mf без учёта регистра. Отклонять URL, UNC/сетевые пути, каталоги и прочие расширения; не скачивать файлы. Проверять размер: не пустой, не больше 50 MiB; константу документировать как ограничение прототипа. Проверки файла выполнять вне Qt. Не выдавать произвольное чтение/раздачу файла через HTTP. В будущем агент должен получать file_id из доверенного загрузчика, а не придумывать локальные пути; внедрение этой границы не входит в текущее ТЗ. Полный путь не включать в успешные ответы и новые логи плагина.

object_id — непрозрачная непустая строка, стабильная для живого объекта в пределах сессии плагина. Одинаковые имена файлов не являются одинаковыми ID. Допустим простой реестр с последовательными ID и проверкой принадлежности узла текущей сцене; не сохранять удалённый узел как действующий объект и не переиспользовать выданные ID. После перезапуска/очистки сцены старый ID может стать недействительным. Не сериализовать UM-объект и не искать по имени.

Считать моделью верхний пользовательский объект: mesh-узел или группу с mesh-потомками. Вложенные части группы не дублировать отдельными верхними моделями. Исключить root, камеры, платформу, служебные узлы без печатной геометрии и G-code preview. Для группы размеры охватывают её mesh-потомков. Если для корректного фильтра нужны декораторы STE, подтвердить их по исходникам и описать в отчёте.

Форма элемента списка (значения иллюстративны):

```json
{
  "object_id":"model-1",
  "name":"bracket.stl",
  "build_plate":0,
  "is_group":false,
  "bounds":{
    "coordinate_system":"uranium_world_y_up",
    "unit":"mm",
    "min":{"x":-10.0,"y":0.0,"z":-15.0},
    "max":{"x":10.0,"y":40.0,"z":15.0},
    "size":{"x":20.0,"y":40.0,"z":30.0}
  }
}
```

build_plate может быть null, если декоратор не даёт номера. bounds у списка допускает null при недоступной геометрии; get_model_bounds в этом случае возвращает понятную ошибку. Размеры конечные, неотрицательные; допустима плоская модель с нулём по одной оси. Использовать мировые преобразования и реальную геометрию; не оценивать размеры по имени, размеру файла или LLM. Для группы учитывать объединение границ mesh-потомков без расширения пустым origin служебного родителя.

Успешные data внутри существующего {ok:true,data:...}:

- list_models: {"models":[...]} — пустая сцена даёт пустой массив, не ошибку.
- get_model_bounds: {"object_id":"model-1","bounds":...} — схема bounds та же.
- load_model: {"file_name":"bracket.stl","objects":[...]} — только объекты, подтверждённо добавленные этой загрузкой. Один файл может дать несколько моделей/групп.

## Запуск и подтверждение загрузки

1. На Qt проверить активную машину, сохранить её идентичность и исходные адресуемые узлы. Не начинать импорт поверх G-code preview: штатный readLocalFile может вызвать deleteAll. Обнаружить это состояние по подтверждённому API/декоратору и вернуть ошибку до импорта. Существующие модели сохраняются.
2. Подключить необходимые сигналы до readLocalFile; нормализовать путь для сопоставления уведомлений. Чужой файл, ранний fileLoaded или появление постороннего узла сами по себе не подтверждают нашу загрузку.
3. Запустить readLocalFile в коротком Qt-вызове. Дать queued-событиям пройти, проверять результат отдельными Qt-вызовами; ждать только в HTTP-worker. Проверить fileCompleted своего файла и фактические новые модели в той же сцене/машине. Если выбран иной обоснованный критерий завершения, описать его и подтвердить подменами и runtime.
4. Общий бюджет ожидания загрузки — 10 секунд; отдельный Qt-вызов не должен каждый раз заново получать полный бюджет. Действующий socket timeout HTTP — 15 секунд; для ручных клиентских команд задать больший timeout. Если реальные выданные файлы не укладываются, зафиксировать ограничение и вынести асинхронный operation_id/polling на согласование, не расширять HTTP-контракт автоматически.
5. Повторная загрузка файла — отдельный импорт, не no-op. На время загрузки блокировать конкурирующий load_model и изменения режима/профилей/материалов через общую координацию адаптера, не ждать lock из Qt. Списки и диагностика остаются читаемыми. Ручной параллельный импорт/очистка сцены не поддерживаются в этом прототипе; обнаруживаемую смену сцены/машины считать ошибкой, не приписывать чужую геометрию нашей операции.
6. Timeout после запуска не отменяет штатный job: он может добавить модель позже. Возвратить явную неопределённость с рекомендацией list_models, без автоматического повтора/удаления. Не допускать нового импорта поверх ещё незавершённого нашего job; небольшой active-load контекст сохраняется до подтверждённого завершения либо shutdown. Если завершение не пришло, сообщить необходимость перезапуска, не выдумывать отмену. Не вводить универсальный менеджер задач.
7. На завершении/ошибке/shutdown убрать собственные подписки/ссылки в безопасном Qt-контексте; сохранить отмену просроченных pending-callback. Синхронный load_model из Qt-потока отклонять до запуска.

Ошибки структуры/типов — прежний JSON-RPC -32602. Валидный запрос с отсутствующим файлом/объектом, неподдерживаемым файлом, неподключённым слайсером, отсутствующей машиной, занятостью, неудачным импортом, недоступными границами или timeout — {ok:false,error:{code,message}}, MCP isError=true. Имена новых кодов закрепить в docs/API_CONTRACT.md. Ошибка reader, пустой результат или setter без новых узлов не считаются успешной загрузкой. Техническое исключение не превращать в Unknown tool; не возвращать traceback браузеру.

## Проверки и приёмка

Автоматические проверки по смыслу, без заданного количества:

- Валидация path/object_id/лишних полей, расширения/размера/существования файла; отсутствие запуска на неверном запросе.
- Пустая сцена, фильтрация служебных узлов, группа и несколько объектов, одинаковые имена и разные стабильные ID, удалённый/устаревший ID.
- Мировые границы после преобразования, правильные оси/мм, группа без фиктивного расширения origin, отсутствующие/неконечные границы.
- Отложенное добавление: один fileLoaded не успех, fileCompleted с пустым результатом не успех, чужой сигнал не успех, корректная загрузка с несколькими объектами успешна.
- Ошибка reader/API, отсутствие машины, смена машины/сцены, preview, конкурирующие записи, timeout до/после старта, позднее завершение без повтора, shutdown и очистка подписок.
- MCP list/call/error, все прежние проверки, синтаксис Python 3.5. Fake-сцена не заменяет runtime-приёмку.

Ручной прогон после ревью координирует основной чат. Перед ним сохранить проект, завершить приёмку ТЗ 03 либо явно зафиксировать её незакрытые пункты. Hybrid 530 V5.2.4, classic, без текущего слайсинга. Зафиксировать машину/режим/качество/материалы и исходную сцену. Исполнитель готовит в plugin/README.md последовательные PowerShell-команды для tools/list, list_models, load_model и get_model_bounds с текущим портом и пользовательским путём к файлу.

Проверить небольшой известный STL, OBJ и 3MF через mesh-импорт; UI и повторные чтения подтверждают объекты/габариты. Для контрольной геометрии с известными размерами сравнить размеры с учётом осей и штатного автомасштабирования. Проверить группу/несколько моделей, повторную загрузку, неизвестный ID и неверный файл. Убедиться, что 3MF не открыл диалог workspace и не заменил глобальные настройки/машину; object overrides описать отдельно. При отсутствии файла формата зафиксировать непроверенный пункт. Проверить сохранность исходных моделей. Очистку тестовых объектов пользователь выполняет штатным UI, инструмент удаления ещё не реализуется.
