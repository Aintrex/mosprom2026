## Цель и границы

По object_id из list_models можно переместить, повернуть, масштабировать и удалить верхнюю модель/группу. После операции вернуть фактически прочитанное состояние и габариты. Действие должно быть штатной UM.Operation с поддержкой пользовательского Undo, а не прямой записью выдуманной сцены.

Прочитать AGENTS.md, COORDINATION.md, модели/адаптер/актуальность нарезки и экспорт. Сначала git status, сохранить чужие незавершённые изменения. Сеть, LLM, UI, custom-профили и авторасстановка не входят в этот объём. Python 3.5; без новых зависимостей и отдельного геометрического движка.

## Реальные API

В справочном Uranium читать UM/Operations/TranslateOperation.py, RotateOperation.py, ScaleOperation.py, RemoveSceneNodeOperation.py, GroupedOperation.py и OperationStack.py; методы SceneNode и UM/Math/Quaternion.py. Штатные примеры — plugins/Tools/RotateTool/RotateTool.py и ScaleTool/ScaleTool.py. В STE смотреть steslicer/Scene/SteSlicerSceneNode.py и BuildVolume.checkBoundsAndUpdate.

- TranslateOperation(node, translation, set_position=True) задаёт абсолютную мировую позицию. Без set_position это относительный сдвиг — не перепутать.
- RotateOperation принимает Quaternion и rotate_around_point; Quaternion.fromAngleAxis ожидает радианы, внешние углы у нас в градусах. Нельзя передать градусы напрямую или опустить центр и неожиданно перенести модель к origin. Native RotateTool сохраняет node.getPosition как pivot; поведение с родителем проверить.
- ScaleOperation с set_scale=False/add_scale=False/relative_scale=False применяет множитель, а не абсолютный итоговый scale. Native ScaleTool использует scale_around_point=node.getWorldPosition. Не использовать relative_scale=True, который в этой версии имеет другую семантику.
- OperationStack.push может тихо не выполнить операцию при занятом внутреннем lock. Один push не считается подтверждением: после него нужны фактические преобразование/сцена.
- RemoveSceneNodeOperation снимает parent, обновляет Selection и needsSlicing. Не вызывать deleteAll и не удалять файл модели с диска.

Если API наследованной группы/родителя не позволяет честно обеспечить выбранную семантику, отклонить такую ситуацию с явным ограничением до записи и описать её. Не копировать mesh для видимости результата, не изменять чужие операции и не чинить дистрибутив.

## Контракт

Оси сохраняют текущий uranium_world_y_up: Y — высота, X/Z — стол; координаты мм, угол градусы, scale — безразмерные множители. Печатную модель и верхнюю группу брать только через текущий ModelRegistry; части группы отдельно не адресуются. Служебные root/камера/платформа/preview не являются допустимой целью.

| Инструмент | Аргументы | Семантика |
| --- | --- | --- |
| move_model | {"object_id":"model-1","position_mm":{"x":0,"y":10,"z":0}} | Абсолютная мировая позиция origin модели |
| rotate_model | {"object_id":"model-1","axis":"y","angle_degrees":90} | Относительный поворот вокруг мировой оси через origin модели |
| scale_model | {"object_id":"model-1","factors":{"x":1,"y":1,"z":1}} | Умножение масштаба, origin остаётся на месте |
| delete_model | {"object_id":"model-1"} | Удаление одной модели/верхней группы из сцены |

Аргументы и вложенные объекты имеют только перечисленные поля; object_id непустая строка, ось только x/y/z, числа конечные без bool и строк. Масштаб строго положителен; зеркалирование/нулевой scale запрещены. Для прототипа факторы от 0.01 до 100 включительно — документированная техническая граница, не предел принтера. Очень большие/непредставимые мировые координаты и преобразования отклонять, не допускать NaN/inf после операции.

get_model_state {object_id} возвращает текущее состояние для подтверждения/восстановления: object_id, position_mm, world_transform (матрица 4x4 конечных чисел), bounds с прежней схемой и признак outside_build_area, если он надёжно доступен. Не использовать Euler-углы как единственный источник истины: порядок/неоднозначность поворотов мешают проверке. Углы по оси проверяются матрицей и контрольной геометрией.

Успешная мутация возвращает object_id и фактические before/after состояния. delete_model возвращает removed_object_id и подтверждение отсутствия; после него прежний ID даёт model_not_found. Если пользователь сделает Undo и объект вернётся, его новый ID берётся из list_models; старый ID не назначать другому объекту.

Оболочка {ok,data}/{ok:false,error}, MCP isError и -32602 как прежде. Предложенные новые ошибки: model_transform_not_applied, model_transform_unsupported, model_operation_busy. Внутреннее исключение не Unknown tool; traceback/приватные пути не отдавать браузеру.

После интеграции агента сохранить его единый ToolRegistry.validate/list_tools/call. Четыре изменяющих инструмента добавить в is_mutating: иначе агент не остановится после их неопределённой ошибки и может разрешить их в вопросе о возможностях. get_model_state остаётся чтением. Агентные снимки нарезки должны консервативно учитывать новые мутации; не менять сам цикл LLM или HTTP ради регистрации этих методов. Добавить одну проверку новой мутации через общий реестр и остановки агента после ошибки, сохранив действующие интеграционные сценарии.

## Выполнение

1. Все чтения/изменения узлов, создание/push операций, Selection и проверка BuildVolume — Qt через существующий мост. Поиск ID повторить в момент записи, проверить принадлежность той же машине/сцене/платформе. Не выполнять геометрию в HTTP-worker.
2. Общий guard запрещает изменение во время импорта, нарезки, экспорта и другой мутации. Не создавать независимый lock, позволяющий обойти текущую защиту. Read tools остаются доступны.
3. Сохранить before, выполнить штатную операцию и перечитать after. Сравнение чисел с допуском, не строками. No-op поворот 0/кратный полному обороту или scale=1 не создаёт лишнюю операцию и не портит действующий slice.
4. Штатное auto-drop может опустить модель на стол. Preferences не менять молча, фактическую позицию не подменять запрошенной. Если зависимый перенос делает запрос не подтверждённым, описать его/вернуть понятное предупреждение или отказ согласно документированному контракту; тестировать эту границу в runtime.
5. Для действительно изменённой геометрии немедленно инвалидировать прежнюю нарезку/будущий экспорт. Обновить проверки положения в BuildVolume; выход за пределы сообщать честно, не масштабировать/переносить автоматически. Не выдавать применённое, но непригодное положение за готовность к печати.
6. После удаления проверить scene/registry и неизменность остальных моделей. Группа удаляется целиком, служебные объекты и исходные файлы сохраняются. Не подтверждать исчезновение только по локальному массиву.
7. Timeout/shutdown по существующему мосту: pending callback отменяется, после начатой мутации результат может быть неопределённым. Автоповтор/откат не выполнять; предложить перечитать get_model_state/list_models. Undo остаётся пользовательским штатным действием.
