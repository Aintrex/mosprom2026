## Что сделать

1. Сообщения ассистента: небольшой безопасный набор Markdown — абзацы/переносы, **жирный**, выделение, списки, inline-code и fenced code. Не нужна полная совместимость с CommonMark или тяжёлая библиотека. Создавать DOM-узлы/текст; текст LLM и имена файлов не исполнять как HTML. Не подключать CDN/удалённые шрифты/картинки, не ослаблять CSP. Неподдержанный формат оставлять читаемым текстом, rawHTML показывать буквально. Не внедрять разметку в пользовательские данные/JSON. Ссылки поддерживать только при безопасной whitelist-схеме, иначе оставить текстом; Markdown-изображения не должны вызывать внешние запросы.
2. Карточки инструментов: человекочитаемые русские названия и короткий фактический итог. Например: «Высота слоя изменена:0.10→0.12мм», «Высота слоя:0.12мм», «Модель загружена:…», «Размеры по осям X/Y/Z:…мм», «Выбран принтер…», «Нарезка запущена, ожидаем завершения». Использовать реальные поля ответа, не придумывать отсутствующие before/оценки/успех. Нет универсальной простыни JSON в основном потоке.
3. Ошибки: понятный заголовок, объяснение и безопасный следующий шаг. Различать отказ до запуска (executed=false), неизвестный исход native-операции, сетевой timeout LLM, реальный failed/stale, прекращённое наблюдение. Не говорить «ничего не изменено» по одному timeout или отсутствию started. Не создавать кнопку автоматического повтора изменения. Технический код/JSON сохранить в сворачиваемом «Технические детали» с текстовым выводом: пригодится приёмке, но по умолчанию закрыто. Для неизвестного инструмента/формы ответа — честная нейтральная карточка с деталями, без ложного успеха.
4. Статусы slice/export и время/расход: русские подписи и единицы из результата. Не показывать rawJSON по умолчанию. Progress=null означает неизвестный прогресс, не0/100. Запуск, idleLLM, завершение и фактический файл — разные состояния; наблюдение stopped не означает остановку engine. Download-ссылки, проверка trusted URL, uploads и контракты сохраняются.
5. Читаемая вёрстка для360/1024/1440px: без горизонтального переполнения страницы, разумная ширина сообщений, нормальные отступы списков/кода, длинное имя файла/слово не ломает чат; технический pre может иметь собственный scroll. Не делать несвязанную смену бренда/фреймворка. Details доступны клавиатурой, состояния не передаются только цветом.
