## Функциональные требования

### 1. Мост в основной поток

- Все обращения к приложению, стеку и контейнерам из HTTP worker проходят через `app.callLater`.
- Сам запрос не должен блокировать event loop Qt. Для коротких get/set достаточно ожидания результата в HTTP worker через stdlib Event/lock и ограниченный timeout; отдельная универсальная система задач не нужна.
- Ожидание не бесконечное: для этих операций ориентир 5 секунд, меньше таймаута HTTP. Исходное исключение не терять; клиенту вернуть понятную ошибку, техническую причину безопасно залогировать.
- Не создавать deadlock при вызове из основного потока: определить этот случай и выполнить короткую операцию прямо либо явно запретить такую точку входа до ожидания.
- Если timeout наступил до начала callback, отменённый callback позже не должен изменять настройки. Если выполнение уже началось и завершение неизвестно, не обещать откат или отсутствие изменения; сообщить неопределённость и рекомендовать повторное чтение. Не повторять set автоматически.
- После shutdown новые обращения завершаются понятной ошибкой. Не возвращать наружу живые Qt/UM-объекты, только JSON-совместимые данные.

### 2. Два реальных инструмента

Сохранить существующий `assistant_status` и добавить:

| Инструмент | Аргументы | Поведение |
| --- | --- | --- |
| `get_setting` | `{"key":"layer_height","scope":"global"}` | Прочитать фактическое значение активного глобального стека |
| `set_setting` | `{"key":"layer_height","scope":"global","value":0.2}` | Проверить аргументы, прочитать before, изменить userChanges, прочитать after |

На этом этапе `scope` обязателен и принимает только `global`; `key` — только `layer_height`. Это намеренно ограниченный объём, не универсальный движок настроек. JSON Schema и серверная проверка должны совпадать; лишние поля отклонять.

Значение set — конечное число, больше нуля; `bool`, строку, null, NaN/Infinity отклонять. Жёсткие minimum/maximum из текущего стека учитывать, если доступны; предупреждения слайсера не приравнивать автоматически к жёсткому запрету. Не выдумывать постоянные ограничения для всех принтеров. Для ручного прогона выбрать допустимое значение под активное сопло/профиль.

Нет активного стека, ключ не поддерживается, нет подключения к приложению, timeout, ошибка API и отсутствие подтверждённого изменения — отдельные диагностируемые ситуации.

### 3. Результаты и MCP

Успех get:

```json
{"ok":true,"data":{"key":"layer_height","scope":"global","value":0.2,"unit":"mm"}}
```

Успех set (числа здесь только пример):

```json
{"ok":true,"data":{"key":"layer_height","scope":"global","before":0.2,"after":0.24,"unit":"mm"}}
```

Операционная ошибка:

```json
{"ok":false,"error":{"code":"no_active_machine","message":"В STE Slicer не выбрана активная машина"}}
```

MCP помещает результат в `content` как JSON-текст и выставляет `isError` по реальному исходу. Ошибки структуры JSON-RPC, неизвестный инструмент и неправильные аргументы остаются протокольными ошибками, например `-32602` для аргументов. Ошибку неизвестного ключа во внутреннем API не маскировать сообщением «Unknown tool» из общего перехвата KeyError.

Минимальные коды операционных ошибок: `slicer_not_connected`, `no_active_machine`, `setting_unavailable`, `qt_timeout`, `setting_not_applied`, `slicer_error`. Тексты должны помогать понять действие пользователя. Если timeout связан с уже начатой записью, указать, что состояние требуется перечитать.

`tools/list` использует тот же реестр и схемы, которые позже получит LLM. Без слайсера нельзя имитировать успех: либо реальные инструменты отсутствуют в списке возможностей, либо вызов явно возвращает `slicer_not_connected`; выбранное поведение описать. `assistant_status` не должен утверждать, что подключён LLM или реализованы все инструменты слайсера.

## Проверки и приёмка

### Автоматизированные проверки без установленного слайсера

Использовать stdlib `unittest` или уже существующие средства. Проверить:

1. Вызов из worker планирует операцию и получает результат; сам worker не читает и не меняет стек. Подмена scheduler должна действительно разнести постановку и исполнение, а не просто синхронно вызвать callback.
2. Корректное чтение/запись, валидация чисел/области/ключа/лишних полей, отсутствие активной машины, исключение API, timeout.
3. После timeout до старта отложенная запись не исполняется; исключение из callback доходит до HTTP/MCP в ожидаемом виде.
4. MCP вызывает тот же адаптер, ставит `isError` при операционной ошибке и не выдаёт Unknown tool на внутреннее исключение API.
5. Dev-сервер запускается без Qt/UM; Python-файлы сохраняют синтаксис 3.5. Нельзя считать это подтверждением совместимости реального runtime.

### Ручной прогон в выданном STE Slicer

1. Установить/обновить плагин по `plugin/README.md` с сохранением пользовательских данных. Если установленный путь неизвестен, найти его чтением доступных локальных данных либо спросить пользователя. Перед перезапуском сохранить открытый проект.
2. Выбрать Stereotech Hybrid 530 V5.2.4, открыть чат из меню расширений. Для этого задания достаточно режима 3D и пустой сцены; не запускать физическую печать.
3. Прямым запросом к текущему `http://127.0.0.1:<port>/mcp` проверить initialize и tools/list.
4. Вызвать get_setting, сохранить исходное значение. Вызвать set_setting с другим допустимым значением; проверить before/after, повторный get и значение в UI.
5. Восстановить исходное значение через set_setting и подтвердить get/UI. При ошибке изменения не утверждать, что восстановление произошло.
6. Проверить хотя бы некорректное значение и неподдерживаемую область через MCP: приложение продолжает отвечать, настройка не меняется.

Если нет технической возможности управлять GUI, подготовить точные команды для прямых MCP-запросов и короткую инструкцию для пользователя. Не отмечать пункты 1–6 выполненными по результатам подмен или чтения исходников. Выводы разделить: реализация готова к ручной проверке / ручная приёмка пройдена.

Пример MCP-вызова чтения (актуальный порт берётся у запущенного плагина):

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_setting","arguments":{"key":"layer_height","scope":"global"}}}
```
