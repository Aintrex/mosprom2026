## Ключи и источники

Список первого объёма: layer_height, layer_height_0, line_width, wall_line_count, top_bottom_thickness, infill_sparse_density, infill_pattern, support_enable, support_type, support_angle, material_print_temperature, material_bed_temperature, speed_print, retraction_enable, retraction_amount, retraction_speed, cool_fan_enabled, cool_fan_speed, adhesion_type.

Ключи найдены в resources/definitions/fdmprinter.def.json выданного форка. Наследование/override определения Hybrid и поддержка конкретной машины проверяются в runtime. Не использовать ошибочные material_print_temp/material_bed_temp из второй ветки. printing_mode, машина, диаметр сопла, стартовый/конечный G-code, выражения/Python и произвольные настройки не входят в allowlist: режим меняется только существующим set_print_mode.

Тип, options, единица, minimum_value/maximum_value, warning bounds, enabled и settable_globally/settable_per_extruder получить из фактического stack/SettingDefinition, сверив свойства по Uranium UM/Settings/SettingDefinition.py и ContainerStack.py. Не подменять отсутствующее свойство своей догадкой. Параметр, которого нет у текущей машины/экструдера, не становится поддержанным из-за наличия в fdmprinter.

## Контракт

get_setting: обязательные key, scope; scope=global либо extruder. При scope=extruder обязателен extruder_id — непустая строковая позиция из global_stack.extruders, например "0". Для global поле extruder_id запрещено. Число 0 и подпись UI "1" не заменяют runtime-позицию.

set_setting имеет те же поля плюс value. Лишние аргументы запрещены. Внешняя JSON-schema описывает allowlist/области/необязательную позицию и number/boolean/string значения, а точную зависимость полей и тип ключа проверяет общий валидатор. Схема MCP и LLM едина. Сохранить вызовы layer_height/global без extruder_id и прежние value/before/after/unit; дополнительные поля могут сообщать позицию/тип. Обновить старые отрицательные тесты, если ранее запрещённый ключ теперь разрешён, сохранив их смысл на заведомо запрещённом ключе.

Добавить describe_settings {scope, extruder_id?} с теми же правилами области. Возвращать небольшой список allowlist с доступностью, текущим значением и подтверждёнными метаданными: key, type, value, unit, enabled, settable, options, минимум/максимум и warning bounds. Не копировать все 100+ параметров. Нет метаданных — null/явное ограничение. Список не должен менять UI-экструдер или настройки для получения данных.

Ответы сохраняют {ok,data}/{ok:false,error}; MCP isError и JSON-RPC -32602 как прежде. Синтаксические ошибки/неверные поля/значения по allowlist отклоняются до API; отсутствие runtime-настройки/стека/поддержки области — понятная операционная ошибка. Неизвестный ID экструдера не превращать в активный UI-экструдер.

## Валидация и запись

- float/int: только конечные числа, bool не является числом; для int требуется целое значение, дробь не округлять молча. Не принимать строку "0.2" вместо числа. Ограничения брать из текущего профиля; layer_height сохраняет прежнюю проверку >0. Не универсализировать положительность для всех параметров — например, нулевое заполнение может быть допустимо.
- bool: настоящий JSON boolean, не строка/0/1. enum: только ключ из актуального runtime options, не перевод/подпись. Свободный str, list/экструдерные выражения и неподдержанные типы не разрешать для записи.
- Учитывать enabled и разрешение на глобальную/экструдерную запись, если API даёт достоверное запрещающее значение. Для readonly/невычисленного противоречивого определения вернуть отказ, а не писать произвольную строку.
- Жёсткие минимум/максимум запрещают неподходящее значение. Warning bounds — отдельное предупреждение и объяснение, не жёсткий запрет. Релевантные зависимые параметры могут штатно пересчитаться; не обещать сохранение всех derived values.
- Писать только в userChanges **целевого** стека на Qt. Не переписывать встроенный материал/quality, не менять активный в UI экструдер. Фактическое before сохранить и after перечитать из целевого stack, нормализуя значение по объявленному типу; не возвращать запрос как подтверждённое after.
- Использовать существующую общую защиту: активный импорт/слайсинг/экспорт/смена профиля не допускают параллельную запись. Чтения остаются доступны. Изменение настройки инвалидирует прежнюю нарезку и согласованность будущего экспорта. Не обходить guard через новый метод.
- Подтверждённый no-op может вернуть before=after без записи/лишней инвалидации. Таймаут после начала записи остаётся неопределённостью без автоматического повтора/отката; просроченный pending-callback не должен изменить значение позже.

Не добавлять batch setter в этом объёме: один вызов меняет один ключ, что сохраняет понятный журнал и ошибки. Если в будущем понадобится пакетная настройка, сначала согласовать частичный результат и атомарность, не имитировать транзакцию.
