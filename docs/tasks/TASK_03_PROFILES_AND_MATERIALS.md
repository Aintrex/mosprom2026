## Цель и границы

Дать агенту реальные списки встроенных профилей качества и материалов под текущую конфигурацию, возможность выбрать существующий доступный профиль и материал конкретного экструдера и подтвердить фактическое состояние. Названия не заменяют ID, молчаливый отказ API не считается успехом.

Прочитать `AGENTS.md`, `docs/PLAN_SLICER.md`, `docs/API_CONTRACT.md` и текущий код/проверки. Репозиторий: `<REPO_ROOT>`. Проверить git status и сохранить незавершённые изменения. Код одновременно меняет один исполнитель.

Основной код — `slicer/`, схемы и вызовы — существующий `agent/tools.py`. Допускаются небольшие модули для профилей и материалов. Сохранить мост Qt, четыре инструмента ТЗ 01/02 и их контракты. Не менять SPA, HTTP-транспорт и будущие REST-маршруты. Новых runtime-зависимостей, singleton, универсального workflow-движка и скрытого изменения Preferences не добавлять.

Не входят: создание/редактирование/сохранение пользовательского профиля, изменение сопла/машины/платформы, управление моделями, LLM, слайсинг и экспорт. Переключение уже существующего custom quality profile также отложено: выбирать в этом задании только встроенную QualityGroup.

Справочная копия: `<SOURCE_ROOT>/STE-Slicer-master`; Uranium — соседний `Uranium-steslicer`. Исходники читать, не менять и не вшивать пути в плагин.

### Список качества

Пример формы data (ID/названия/значения иллюстративны):

```json
{
  "machine_id":"runtime-machine-id",
  "current":{"quality_type":"fine","name":"Fine","custom_profile_id":null,"has_user_settings":true},
  "profiles":[{"quality_type":"fine","name":"Fine","available":true,"layer_height_mm":0.1}]
}
```

Показывать все группы с честным available, выбирать только доступные. Высота слоя — базовая высота профиля, не текущий пользовательский override; если надёжно вычислить её не удалось, null, не выдуманное число. Чтение не должно менять профиль ради получения информации. Не путать group.quality_type с ID одного из контейнеров глобального стека/экструдеров.

### Список материалов

```json
{
  "machine_id":"runtime-machine-id",
  "extruder_id":"0",
  "current":{"root_material_id":"root-pla","material_id":"resolved-machine-pla","name":"PLA"},
  "materials":[{"root_material_id":"root-pla","material_id":"resolved-machine-pla","name":"PLA","brand":"Generic","material":"PLA","compatible":true}]
}
```

Список строится для указанного существующего экструдера и текущего сопла/диаметра, не из всех материалов установки. Удаляемые пакеты исключать по metadata.removed, как штатные модели. Явно несовместимый материал не выбирать; отсутствующее compatible не подменять true (допускается null). Название, brand/material могут быть null при отсутствии метаданных. Текущий root_material_id и resolved material_id могут различаться, оба нужно сохранить для проверки и восстановления. Отсутствующий материал обозначить current=null.

Не менять активный в UI экструдер ради чтения/выбора по явному extruder_id. В ответе всегда есть позиция затронутого экструдера.

### Выбор и подтверждение

- Повторно получить доступный список в момент записи и проверить ID/доступность: данные после смены материала/сопла могут устареть.
- Перед записью сохранить фактические before; после вызова подтвердить runtime-состояние. При необходимости дать queued-сигналам пройти через отдельные короткие Qt-вызовы, ожидать только в worker с конечным общим бюджетом меньше HTTP timeout.
- Для select_profile after.quality_type должен совпасть с выбранной доступной встроенной группой, пользовательский custom quality profile не должен остаться активным незаметно. Для select_material должны совпасть root ID, целевой экструдер и ожидаемый resolved container из текущего lookup.
- MaterialManager может поменять группу качества в зависимости от материала: возвращать реально полученное качество и заставлять клиента перечитать список профилей. Не обещать, что все зависимые температуры/скорости сохранят прежние значения.
- Состояние после выбора выводить даже при одинаковых отображаемых именах. Повторный выбор фактически активного встроенного профиля/материала — подтверждённый no-op без лишнего setter/диалога.
- Проверять смену активной машины/экструдера/lookup во время операции. Параллельные изменения качества/материала/режима сериализовать простой общей блокировкой адаптера либо отклонять с понятным busy-кодом. Не блокировать ею Qt-поток в ожидании worker.
- Сохранить отмену pending-вызовов при timeout/shutdown и диагностику неопределённости после начатой записи. Автоматического повтора/отката нет.

## Пользовательские изменения и штатные диалоги

Это конкретная особенность исходников, не требование вводить подтверждение на любое действие. `MachineManager.setMaterial` и `setQualityGroup` после изменения могут вызвать `discardOrKeepProfileChanges`; `choice_on_profile_override=always_discard` очищает userChanges, `always_keep` сохраняет, иначе возможен штатный диалог.

В текущем ТЗ автоматические операции **сохраняют пользовательские overrides**:

- Выбор встроенной QualityGroup можно выполнить публичным `setQualityGroup(group, no_dialog=True)` после проверок: подтвердить по исходникам/тестам, что userChanges не очищены. Не вызывать приватные `_setQualityGroup` и обработчики диалога вручную.
- При активном custom quality profile реальная смена встроенного профиля в этом объёме возвращает `custom_profile_active` до записи: пользователь сначала должен явно решить судьбу custom-профиля. Совпадение underlying quality_type само по себе не означает no-op.
- Для материала проверить **до записи**, может ли выбранный штатный путь показать диалог или сбросить userChanges. Если без такого риска выполнить нельзя, вернуть `user_changes_present` с понятным объяснением до вызова setter. Чистое состояние либо проверенная штатная политика always_keep допускают вызов. Случай no-op сначала подтвердить и вернуть без setter.
- Не менять Preferences для обхода диалога, не очищать контейнеры и не отвечать за пользователя на Keep/Discard. Это ограничение MVP явно описать в README и отчёте. Расширение с явной пользовательской политикой можно обсудить отдельным заданием.
- Сохранённые overrides могут удерживать layer_height прежним при смене базового профиля. Успех определяется выбранной группой и контейнерами, а не обязательным изменением отображаемой высоты слоя.

## Формат результатов и ошибок

Для всех четырёх инструментов общий формат `{ok:true,data:{...}}` либо `{ok:false,error:{code,message}}`; MCP выставляет isError. Пример выбора материала:

```json
{"ok":true,"data":{"extruder_id":"0","before":{"root_material_id":"root-pla","material_id":"resolved-pla","name":"PLA"},"after":{"root_material_id":"root-petg","material_id":"resolved-petg","name":"PETG"},"quality_type_after":"fine","has_user_settings":false}}
```

Для выбора качества data: `{before:{quality_type,name,custom_profile_id},after:{quality_type,name,custom_profile_id},has_user_settings}`. Фактические значения before/after не заменять запрошенным ID без чтения.

Некорректная структура/типы/лишние поля — JSON-RPC -32602. Операционные ошибки: прежние ошибки подключения/Qt/API и, по смыслу, `extruder_not_found`, `profile_not_available`, `material_not_available`, `custom_profile_active`, `user_changes_present`, `selection_not_applied`, `selection_busy`. Неизвестный ID после корректного синтаксиса — операционная ошибка, без записи. Внутренний KeyError не выдавать за Unknown tool. При ошибке после начатой записи указать, что нужно перечитать списки/состояние; если реальный before/after неизвестен, не утверждать восстановление.

## Проверки и приёмка

Сохранить 45 существующих проверок и добавить проверки значимого поведения:

- Qt-поток для всех чтений и записи; dev-режим без Qt/UM, отсутствие машины/менеджера/экструдера/материала, JSON-сериализуемость.
- Реальные ID из подмен намеренно отличаются от названий; root/resolved material ID различны; выбор позиции 0 не меняет позицию 1 и активный UI-экструдер.
- Доступные/недоступные quality groups, изменившийся lookup, чужие/неизвестные ID; операции чтения не вызывают setter.
- Подтверждённый выбор и no-op; setter без изменения не считается успехом; отложенное применение/ошибка API/timeout/shutdown/конкурирующая запись.
- Пользовательские overrides сохраняются; политика с потенциальным discard/диалогом блокируется до изменения материала; custom quality group не сбрасывается; изменение материала отражает реальное последующее качество.
- MCP list/call/error и старые схемы; синтаксис 3.5. Не вводить обязательное количество тестов и не копировать тестами реализацию.
