# ТЗ 05 Реальный слайсинг 3D и его результат

Статус: готово к передаче нашему исполнителю роли 1. Это первая часть этапа 04 плана. ТЗ 04 реализовано и прошло 94 автоматические проверки с предыдущими заданиями; ручная приёмка ТЗ 03/04 ещё открыта. Подготовка следующего задания не закрывает её.

## Цель

Через MCP запустить штатный CuraEngineBackend в режиме classic, получить идентификатор запуска, читать настоящий статус и прогресс, после завершения получить время печати и расход материала из STE Slicer. Результат нельзя вычислять собственной приблизительной формулой или подменять симуляцией.

Первый законченный сценарий: небольшая модель уже находится на столе → start_slicing → polling get_slicing_status → подтверждённое завершение engine → get_slicing_result → сравнение с UI/предпросмотром.

## Объём и файлы

Основная логика — slicer/; допустим один небольшой slicing.py. Новые инструменты добавить в существующий ToolRegistry. Минимально расширить lifecycle Extension/адаптера для подписок и завершения; не заменять рабочий QtBridge. Обновить docs/API_CONTRACT.md, plugin/README.md и корневой README там, где меняется фактическая готовность.

Python 3.5, стандартная библиотека и PyQt5 из приложения. Сеть/ожидание — вне Qt, все чтения/записи app/scene/stack/backend/PrintInformation — на Qt через app.callLater и существующий мост. Наружу возвращаются JSON-данные, не QObject/UM-узлы.

В этом задании только classic. Не реализовывать 5D-слайсинг, экспорт файлов, отмену отдельным MCP-инструментом, новые настройки, преобразования моделей, LLM, Preferences ключа, upload или SPA. Существующая ручная отмена в UI должна корректно отражаться в статусе. Операции физического принтера не выполнять.

## Подтверждённые места в исходниках

STE: <SOURCE_ROOT>/STE-Slicer-master. Uranium: соседний Uranium-steslicer. Пути не добавлять в runtime-код, исходники не менять.

- plugins/CuraEngineBackend/CuraEngineBackend.py: forceSlice вызывает markSliceAll и slice; это запуск, не результат. forceSlice может затронуть несколько платформ — первый объём ограничить одной непустой активной платформой.
- Там же: slicingStarted, slicingCancelled, backendStateChange, processingProgress, backendError, backendQuit; прочитать _onStartSliceCompleted, _onSocketError, _onSlicingFinishedMessage и сбросы при изменении сцены/настроек.
- _onSlicingFinishedMessage испускает BackendState.Done и progress=1 **до** подстановок в G-code и последней очистки _slicing. Финальную проверку выполнить отдельным Qt-callback после обработки этого сигнала.
- slice может выдать progress=1 без нового слайсинга, если ничего не нужно нарезать. В начале вызывается stopSlicing, который испускает NotStarted. Нельзя считать любое progress=1 успехом или любой начальный NotStarted ошибкой.
- UM/Backend/Backend.py: BackendState.NotStarted/Processing/Done/Error/Disabled. У базового Backend нет подтверждённого публичного getter текущего состояния; не выдумывать getState. Подписываться на сигналы и, для проверки занятости в этом форке, при необходимости локально читать подтверждённые _slicing/_start_slice_job/_generate_basement_job/_process_layers_job. Приватные чтения изолировать и описать, приватные поля backend не менять.
- steslicer/BackendManager/BackendManager.py: getCurrentBackend, getBackendByType, currendBackendChanged. Нужна идентичность фактического backend объекту classic, не только совпадение названия режима.
- steslicer/PrintInformation.py: currentPrintTime, materialLengths, materialWeights; расчёт обновляется по printDurationMessage. UM/Qt/Duration.py реализует int(duration) как секунды, не getTotalSeconds.
- PrintInformation.materialLengths в этой сборке содержит **метры**: _calculateInformation делит длину в мм на 1000. Наш JSON должен отдавать length_mm после перевода. materialWeights — граммы. Не приписывать элементам списков позиции экструдера без подтверждения порядка; для MVP достаточно честных итоговых сумм.
- _onPrintTimeMaterialEstimates получает engine-оценки для конкретной платформы. Обеспечить свежесть и принадлежность данных именно текущему запуску, а не брать ненулевые числа старого проекта.
- Сгенерированный engine G-code находится в scene.gcode_dict по платформам; источник подтверждается plugins/GCodeWriter/GCodeWriter.py. В ТЗ 05 проверяем наличие свежих данных завершённой нарезки, но не пишем их на диск своим генератором.

## Контракт трёх инструментов

Аргументы валидируются единым реестром до API; лишние поля запрещены. slice_id — непрозрачная непустая строка, не путь и не номер из UI. Хранения в памяти достаточно: один активный запуск и последний завершённый результат, без БД/универсального job manager.

| Инструмент | Аргументы | Поведение |
| --- | --- | --- |
| start_slicing | {} | Короткий запрос запуска; возвращает slice_id и queued/running, не ждёт всю нарезку |
| get_slicing_status | {"slice_id":"slice-1"} | Снимок состояния выбранного запуска, прогресса и актуальности |
| get_slicing_result | {"slice_id":"slice-1"} | Только подтверждённый завершённый и актуальный результат |

Оболочка прежняя: {ok:true,data:...} или {ok:false,error:{code,message}}; MCP isError=true для операционной ошибки, неверная структура/типы — JSON-RPC -32602. В dev-режиме без app — slicer_not_connected, без имитации успешного engine.

Пример формы статуса; значения иллюстративны:

```json
{
  "slice_id":"slice-1",
  "state":"running",
  "progress":0.42,
  "printing_mode":"classic",
  "backend_id":"CuraEngineBackend",
  "build_plate":0,
  "valid":false,
  "error":null
}
```

state: queued/running/completed/failed. progress — конечное число 0..1 или null, когда engine не дал долю. Переход к completed только по подтверждению ниже. При отмене/ошибке — failed с объясняющим error. valid означает, что completed-результат всё ещё относится к текущей сцене/настройкам. Неизвестный ID — операционная ошибка; не подменять его последним запуском.

Результат data:

```json
{
  "slice_id":"slice-1",
  "printing_mode":"classic",
  "backend_id":"CuraEngineBackend",
  "build_plate":0,
  "print_time_seconds":3600,
  "material":{"length_mm":12000.0,"weight_g":36.0},
  "source":"ste_slicer"
}
```

Неизвестное значение — null с объяснённым ограничением, не выдуманный ноль. Ноль допустим только как подтверждённое значение. Оценки времени/расхода — прогноз слайсера, не фактический замер физической печати. Не обещать точность выше исходных данных/округления PrintInformation.

## Жизненный цикл и защита результата

1. При старте на Qt проверить машину, classic и matching backend, существующие печатные модели на активной платформе, отсутствие preview/незавершённого импорта и другого слайсинга. В MVP разрешена только одна непустая платформа. Неподходящее состояние отклонить до forceSlice.
2. Если general/auto_slice включён, вернуть явное ограничение и попросить пользователя выключить автоматическую нарезку в UI для этого прототипа. Preferences не менять молча. Ручной параллельный запуск/редактирование сцены не поддерживаются; обнаруженный конфликт не выдавать за нашу нарезку.
3. Захватить активный backend, stack, scene/root, платформу, контекст геометрии и настроек; подключить сигналы **до** запуска. Начальную занятость нельзя определять только отсутствием собственного slice_id. Подписки, их типы/поток и отсутствие пересечения со старым job подтвердить по fork API.
4. Вернуть slice_id быстро, в бюджете обычного QtBridge. queued не означает, что engine уже начал работу. На slicingStarted/Processing подтвердить начало; собственные старые/чужие сигналы не должны закрывать новый запуск.
5. Пока queued/running блокировать через существующую координацию адаптера конкурирующие записи: set_setting, режим, качество, материал и load_model. Чтения/диагностика/status доступны. Существующий set_setting ещё не участвует в общей блокировке — добавить минимальную защиту. Не ждать lock на Qt и не вводить вторую конфликтующую блокировку.
6. Ожидание — сигналы плюс небольшой Qt QTimer при необходимости. Нельзя держать HTTP-запрос до завершения, делать sleep/wait или тяжёлый цикл на Qt. Опрос клиента раз в секунду достаточен; REST-события для frontend в этом ТЗ не реализуются.
7. completed требует подтверждённого начала и Done от захваченного backend, затем отдельной короткой Qt-проверки той же платформы/сцены/машины, свежих engine-данных G-code и свежей PrintInformation. Один Done/progress=1 или старый gcode_dict недостаточны. Нельзя очищать engine-буферы собственноручно ради корреляции. Если надёжная принадлежность результата не подтверждается — ошибка/неопределённость, не успех.
8. Учесть задержку оценок, отмену UI, ошибки подготовки модели/настроек, backend Error/Disabled/quit, недоступный движок и ранние возвраты. Не проглатывать исключения и не превращать отсутствие публичного метода в успешную заглушку. Если точная причина не дана API, сообщить общий реальный отказ со ссылкой на лог, а не придуманный диагноз лицензии.
9. Конечный бюджет операции прототипа — 180 секунд от принятия. По истечении зафиксировать failed/slicing_timeout, без автоматического повтора. Это не отмена engine: пока не подтверждён его выход, нельзя отпускать защиту так, чтобы новый запуск/запись пересеклись с продолжающимся job. Статус объясняет необходимость ручного Stop/ожидания или перезапуска при отсутствии завершения.
10. После завершения изменение печатной геометрии/параметров, режима, материала, качества, машины или платформы делает прежний результат неактуальным: valid=false, get_slicing_result возвращает slice_result_stale. Изменение камер/выделения и добавление служебных узлов предпросмотра не должны ошибочно портить результат. Минимальный механизм ревизии/снимка выбрать по реальным сигналам; не строить универсальную систему снимков всего приложения.
11. При shutdown отключить собственные сигналы/таймеры на Qt, отменить pending-callback, снять свои ссылки/блокировки. Не завершать чужой процесс engine и не выдавать незавершённый запуск за completed. Не переподключать и не вызывать старые callbacks после закрытия.

Имена новых ошибок согласовать и зафиксировать в API_CONTRACT: как минимум empty_scene, unsupported_slicing_mode, slicing_busy, auto_slicing_enabled, slice_not_found, slice_not_ready, slice_result_stale, slicing_failed/slicing_timeout. Не расширять действующие аргументы старых инструментов несвязанными настройками.

## Значимые проверки

- Валидация, dev/no app, отсутствие машины/модели, неверный режим/backend, несколько платформ, preview, auto-slice и уже занятый engine: никакого forceSlice.
- Быстрый ответ start и последовательность queued → running → completed, фактический прогресс/null, корректные slice_id и неизвестный ID. Обычный get_setting/list_models остаётся доступен.
- Progress=1 без начала, прежний Done/G-code/время, чужая платформа/backend, ранний NotStarted, задержанные оценки, Done до финализации: не считать успехом.
- Реальные значения из подменённого PrintInformation, секунды Duration, метры → мм, граммы, null вместо выдуманных данных.
- Отмена/ошибка job/engine quit/timeout и позднее завершение; нет повторного запуска, раннего снятия защиты и ложного completed.
- Блокируются все перечисленные записи, включая set_setting; смена пользователем геометрии/машины/настроек инвалидирует результат, а камера/выделение — нет.
- Shutdown, подписки/таймеры, поток Qt; прежние 94 проверки и синтаксис Python 3.5. Новое количество тестов не является критерием качества.
