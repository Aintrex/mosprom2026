# Исправление числовых аргументов и преобразований моделей

**Кому:** существующему разработчику интеграции STE Slicer. **Статус:** назначается ведущим после публикации этого ТЗ. **Приоритет:** сначала числовой setter, затем диагностика и исправление подтверждённых проблем преобразований. UI и файлы другого участника описаны отдельно в `TASK_UI_FILES_AND_MODEL_CONTROLS.md`.

## Что сообщил пользователь

1. При просьбе установить `layer_height=0.12` агент получает `invalid_tool_arguments`, `stage=validation`, `executed=false`; `arguments_summary.field_types.value="string"`, исходное значение остаётся0.1. Модель затем заявляет, что отправила JSON-число, которое «транспорт превратил в строку». Диагностика этого не доказывает: она подтверждает строку на входе валидатора и отсутствие native-запуска. Причина появления строки ещё требует проверки.
2. Импорт STL работает по пользовательскому наблюдению, но попросить агента повернуть загруженную модель не получается. Конкретные аргументы/код отказа поворота пока не представлены. Это жалоба на незавершённый сценарий, а не доказательство дефекта RotateOperation.

Состояние другой сцены или режима из ответа модели не считать причиной отказа типа. Не менять `cylindrical_layer_height` вместо запрошенного `layer_height`, не переключать режим и не приписывать точные проценты времени/прочности без расчёта движка.

## Перед кодом

Прочитать AGENTS.md, COORDINATION.md, текущие service/tools/llm/settings/transforms и тесты. Сохранить чужие документы/очищенные Word-копии. Сначала прислать ведущему короткий технический план: воспроизведение, обнаруженная граница ошибки, выбранный способ типизации/исправления и список файлов. Не ограничиваться усилением SYSTEM_PROMPT: прежнее пояснение «0.12, не строка» уже существует и не решило пользовательский случай.

Работать последовательно в общей папке; второй участник UI не должен одновременно менять этот runtime. Git add/commit/push, AppData, реальный провайдер/ключ, запуск STE/MCP/принтера исполнителем не разрешены. Для справочных API использовать выданные исходники, путь выяснить локально, не записывать личные пути в Git.

## Часть A Числовые параметры

- Воспроизвести `set_setting` с настоящим JSON-числом0.12 и строкой`"0.12"` в scripted Chat Completions. Проследить тип на выходе клиента, после `json_arguments` и перед адаптером; не публиковать raw provider body, ключ или пользовательские значения в лог. Обычный `json.loads` не считать преобразующим число в строку без доказательства.
- Устранить несогласованность схемы и конкретного ключа: сейчас `value` имеет общий union number/boolean/string для120 ключей. Выбранная схема/выдача инструментов должна однозначно направлять LLM к числам для float/int, bool для bool и строкам options для enum. Использовать единый каталог типов и реестр для MCP/LLM, без второго списка ключей и отдельных неподконтрольных setters. Существующий MCP-контракт сохранять; вариант типизированных схем/инструментов сначала согласовать с ведущим.
- Строгую проверку перед Qt не ослаблять: bool не число, non-finite/единицы/выражения/неверные enum/лишние поля запрещены. Не добавлять общий `float(value)` для любой строки. Если предлагается специальный разбор числовой строки только на границе LLM, описать его отдельным пунктом плана до реализации: точный синтаксис, конечность, единицы, прозрачность преобразования и неизменный строгий прямой MCP. Молчаливое угадывание чисел/области не допускается.
- Доказанный отказ до запуска допускает ограниченное исправление аргументов по схеме и исходному запросу пользователя. Повтор той же ошибочной сигнатуры не должен образовывать цикл. После фактически начатой операции, Qt/network timeout или неизвестного исхода повторов/других записей нет. Сохранять бюджеты8LLM/16tools/120s/30s, не лечить ошибку увеличением лимитов.
- Возвращать компактную полезную диагностику конкретного аргумента: ожидаемый тип/поле, фактический тип, stage и executed; полный общий каталог не должен быть единственным объяснением. UI не обязан отображать raw значения. Не выдавать `arguments: "Не опубликованы"` за доказательство реально отправленного значения.
- Уточнить инструкцию ответа модели: известен тип string у валидатора, native не запущен; причина сериализации не доказана. Не утверждать успех по собственному тексту, не продолжать изменения другого параметра и не обосновывать отказ якобы неподходящим режимом, если ошибка была типовой.

## Часть B Поворот и соседние операции

После части A воспроизвести цепочку upload/file_id → подтверждённый load_model_file → актуальный list_models → get_model_state → rotate_model → readback. Угол — JSON-число, axis — x/y/z, object_id — живой ID из текущего процесса. Проверить, не возникает ли здесь тот же дефект числовых аргументов.

Разделять три исхода: аргументы отклонены; preflight запретил операцию; штатная UM-операция запущена, но результат не подтверждён. Существующие ограничения нужно проверить и объяснить: physics/automatic_drop_down и automatic_push_free, активная платформа, верхний объект/группа и матрица родителя, Preview, импорт/engine/export busy, stale ID. Не отключать физику и не менять Preferences автоматически ради зелёного теста. При исправных аргументах и допустимом контексте проверить RotateOperation/Quaternion по выданному Uranium и подтверждение мировой матрицы. Симметричная модель может визуально выглядеть так же — матрица и readback обязательны.

Точечно проверить move/scale/delete/arrange на том же классе ошибок и гонок. Исправлять только воспроизведённые дефекты, не переписывать весь слой сцены и не добавлять новый упаковщик. Undo, Qt-мост, блокировки и инвалидация прежнего slice/export сохраняются. Если реальный отказ требует данных пользователя, явно перечислить недостающие аргументы/код ошибки, не объявлять поворот исправленным по fake-проверкам.

## Проверки и критерии приёмки

| Сценарий | Требуемое поведение |
| --- | --- |
| Float0.12 для layer_height | В scripted ходе доходит числом; одна native-запись, before/after и отдельный get_setting подтверждены |
| Строка0.12 | Строгий прямой MCP отклоняет до API; агент исправляет только по согласованной политике, без бесконечного повтора и ложного успеха |
| int/bool/enum и scope | Типы/границы/options/extruder_id проверяются, global не получает extruder_id даже null |
| Повтор неверного вызова / native timeout | Нет цикла одинаковых ошибок; после неизвестного запуска нет второго mutating native-вызова |
| Импорт и поворот живого ID | На подменах одна штатная операция и подтверждение матрицы; другой объект не изменён, Undo сохранён |
| Physics/busy/Preview/stale ID | Объяснимый отказ до push операции, без автоматического обхода или обещания успеха |
| Исторический чат после restart | Старые object/file IDs не оживают; актуальные чтения и guard сохранены |
| Секреты и ложные объяснения | Нет raw provider body/личных данных; нет недоказанного утверждения «транспорт превратил число» |

Добавить значимые адресные Python/JS-проверки там, где меняется поведение; выполнить достаточную регрессию и Python3.5/api5. Не ослаблять старые ожидания лишь ради зелёного набора; изменение согласованного поведения объяснять в отчёте. Нативный прогон и реальную LLM оставить отдельной приёмкой пользователя:0.1→0.12/readback/UI→явное восстановление; затем импорт несимметричного STL→поворот→UI/матрица/Undo. Никакая подмена не доказывает послушание провайдера.

Результат: `docs/reports/FIX_TOOL_ARGUMENTS_AND_MODEL_TRANSFORMS_REPORT.md` с причинами, diff, тестами, оставшимися ограничениями и короткими промптами повторной проверки. После отчёта остановиться для ревью; UI-этап и публикацию самостоятельно не начинать.
