# Интерфейс чата вложения и управление моделями

**Кому:** второму участнику, который берёт **UI и файлы**. **Статус:** готовое ТЗ для передачи; существующему разработчику backend оно не назначено. Сначала выполнить frontend в своей копии/ветке, согласовав границы с ведущим. Базовые инструменты чисел/поворота исправляет другой исполнитель по `TASK_FIX_TOOL_ARGUMENTS_AND_MODEL_TRANSFORMS.md`; не исправлять их параллельно в общем runtime.

## Цель

Пользователь видит, какой файл прикреплён, загружен ли он только в чат или уже импортирован в сцену, какой объект выбран и почему действие недоступно. Поворот/перемещение/масштабирование не должны выглядеть необъяснимым отказом. Существующие чат, сохранённые диалоги, Markdown, tool-карточки, прогресс и скачивание сохранить. Figma и полная смена дизайна для этого задания не нужны.

Прочитать AGENTS.md, API_CONTRACT.md, FRONTEND_INTEGRATION.md, CURRENT_VERSION_ACCEPTANCE.md и текущие `plugin/AIAssistant/web/`, server/uploads/downloads. Проверить реальный код, а не считать старую документацию безусловной истиной. Не добавлять личные пути, адреса аккаунтов, ключи, временные логи или приватные файлы в Git.

## 1 Вложения перед отправкой

- Для JPG/PNG/STL/OBJ/3MF показать имя, формат, размер, понятные фазы «загружается / готово / ошибка» и действие убрать из текущей отправки. Лимиты брать из status/контракта, не из второго произвольного списка.
- Для изображения допустима безопасная миниатюра выбранного локального файла; object URL освобождать. Не добавлять загрузку SVG/HTML, внешние картинки, выдачу произвольного локального пути или ослабление CSP. Новые blob/data img-src сначала согласовать, если текущий CSP не позволяет миниатюру.
- У модели показать явное различие: «прикреплена к сообщению» и «импортирована в сцену». Загрузка файла через upload не является импортом, фото не является STL. Повтор принятого сообщения не создаёт повторный upload/import.
- Файл с ошибкой блокирует отправку с объяснением; его можно убрать. Одинаковые имена не подменяют file_id. После неопределённого timeout нет автоматической повторной загрузки/импорта.

## 2 Объекты сцены и простые действия

Нужен компактный блок моделей текущей сцены: имя, выбранный объект, габариты с единицами/осями, кнопка обновить. Данные только из list_models/get_model_state/get_model_bounds текущего процесса. Строка в списке прикреплённых файлов не заменяет живой объект сцены. Старый ID из истории нельзя переиспользовать после restart/delete/import workspace.

Для выбранного объекта предусмотреть понятные действия: повернуть по X/Y/Z на заданное число градусов; переместить в абсолютные мировые координаты в мм; изменить масштаб числовыми коэффициентами. Обозначить, что мировая Y направлена вверх. Удаление тестового объекта — отдельное действие с подтверждением, не удаление исходного STL. Указать доступность штатного Undo.

Перед реализацией согласовать короткий контракт выполнения с ведущим. Предпочитать существующий сервер/реестр/MCP и Qt-мост; не заводить второй backend, произвольный Python, прямой доступ JS к файловой системе или отдельный путь изменения сцены. Формы передают JSON-числа, не строковые DOM.value: пустая строка не становится0, NaN/Infinity/единицы не отправляются. Если кнопка формирует сообщение агенту, это должно быть явно подписано; не выдавать отправку промпта за уже выполненное преобразование. Если используется прямой MCP, результат/ошибка и before/after должны отображаться, инвалидация актуальных slice/download сохраняться. Новые REST-пути без согласования не добавлять.

Показывать причины недоступности: активный запрос/загрузка/engine/export, Preview, неподходящая платформа/объект, автоматическая физика, неизвестный исход операции. Эти запреты не обходить. Если текущий контракт не выдаёт нужную причину заранее, показывать честный отказ из результата и запросить небольшое расширение API у ведущего; не угадывать readiness и не менять Preferences автоматически.

## 3 Ошибки и результаты

- Основной текст: что не получилось, выполнено ли действие, что пользователь может проверить. Для `stage=validation/executed=false` прямо сказать «настройка не менялась этим вызовом»; для неизвестного исполнения — «результат не подтверждён, сначала перечитайте состояние». Не смешивать эти случаи.
- Для ошибки числового типа достаточно назвать параметр, ожидаемый тип и пример корректного числа. Все120 ключей/полная схема — только в закрытых технических деталях, без горизонтального переполнения.
- В карточке подтверждённого преобразования показывать фактический результат/единицы; до readback не писать «модель повёрнута». Текст нейросети не перекрывает ошибку инструмента.
- Сохранить безопасный DOM-Markdown и инертность HTML из сообщений/имён файлов. Не добавлять innerHTML для непроверенного текста. Технические JSON, ID и диагностика остаются доступны, но не заполняют основную ленту.

## 4 История и выходные файлы

Список диалогов, Новый/Открыть/Удалить, статус Saved после файлового ack, разделение выбранного контекста и запрет опасного переключения при pending/busy должны работать как прежде. После восстановления вложение показывается как недоступное с просьбой загрузить заново. История не восстанавливает сцену, старые upload/download/operation IDs и активные операции.

Карточки собственных slice/export и скачивание настоящих G-code/3MF сохранить. Показывать running/completed/failed/stale/unknown, время и расход по фактическим данным. Download появляется после подтверждённого native writer; старый/stale файл не пересоздаётся автоматически. Не генерировать G-code или пустые файлы на frontend.

## Проверки и сдача

1. На offline fixtures проверить ширины360/1024/1440, длинные русские имена, клавиатуру/Tab/Enter и видимый focus. Поля, кнопки и ошибки читаемы без горизонтального скролла.
2. Проверить lifecycle: один и несколько файлов; неверный формат/размер; убрать; timeout; refresh во время pending; выбор другого чата; restart с expired; повтор принятого сообщения без повторного POST/import. Сохранить прежние JS-проверки, добавить только значимые сценарии новых контролов.
3. Проверить передачу numeric0.12/угла15/трёх координат/коэффициентов именно JSON-числами; пустой ввод, boolean и non-finite отвергаются. Ошибка backend не превращается в зелёную карточку.
4. Для моделей — текущий живой ID, успешный readback, busy/physics/Preview/stale и изменение сцены в другом окне. Для файлов — отсутствие чужих локальных путей и автоматического оживления ссылок.
5. Сохранить Python3.5/api5, единый `plugin/AIAssistant`, текущий HTTP/Qt и отсутствие frontend-сборки/новых фреймворков ради задания. Изменения backend/контракта согласовать отдельно; не ослаблять Host/Origin/CSP/лимиты.

Передать исходники в своей ветке/копии и `docs/reports/UI_FILES_AND_MODEL_CONTROLS_REPORT.md`: что изменено, согласованный контракт, проверки, скриншоты с явной подписью offline при fixtures, ограничения. Внешнюю установку, реальный ключ/LLM/native-прогон, слияние и push вmain участник не выполняет без отдельного поручения. Ведущий проверяет diff и проводит интеграцию после сохранённой проверенной основы. Результат не объявлять готовым по одним макетам: кнопки должны иметь проверенный путь до результата, а настоящий STE остаётся отдельной приёмкой.
