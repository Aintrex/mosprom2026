## Результат

Ассистент находит и описывает параметры нужной группы и меняет поддерживаемый параметр через прежние get_setting/set_setting с фактическим readback. Исходный каталог — **120 параметров** в 10 группах, включая прежние 19; ключи и типы подтверждены ведущим по локальным определениям STE и цепочке основного принтера. См. TASK_13_SETTINGS_CATALOG.md.

Это не обещание одновременной записи всех120: машина, режим, профиль, экструдер и enabled определяют runtime-доступность. При противоречии source/runtime — конкретный отказ и отчёт, не подмена метаданных ради числа.

Внешние исходники только читать. Определение hte530v5.2.4 → steprinter530_v5.2.4 → steprinter_v5 → fdmprinter; для120 ключей в этой цепочке не найдено противоречащих type overrides. Проверить используемый API описаний и экструдерные определения. Не копировать внешний JSON целиком/не вшивать SourceSTE-путь в runtime.

Не открывать machine_*, start/end G-code, команды/пути CLI, определения железа и недопустимые режимы. printing_mode остаётся отдельным set_print_mode с подтверждением backend. Reinforcement/экспериментальные поля вне предложенного каталога не добавлять ради числа.

## Подробные метаданные и адресная выдача

Расширить существующий describe_settings. Нельзя читать все120 полных описаний на каждом LLM-ходе.

- К прежним scope/extruder_id добавить необязательные `keys` (1–20 уникальных разрешённых ключей), `category`, `query` (до80 символов), `offset` (целое>=0), `limit` (целое1–30, default20). Категории стабильны и перечислены в схеме. Bool не int, extra fields отклоняются.
- Фильтры пересекаются, порядок каталога стабильный; поиск регистронезависимый по key/краткому названию. Неизвестные category/key — явная ошибка; пустой поиск — settings=[], total=0.
- Уточнение ведущего по плану исполнителя: отсутствие query не фильтрует, явно переданная пустая/пробельная query возвращает0 результатов. Эту разницу документировать. Все аргументы и scope/реальная машина/экструдер проверяются и для пустого результата: ранний return не обходит валидацию.
- Сохранить result.scope/settings/extruder_id; добавить total (после фильтров до страницы), offset/limit/returned, next_offset (null в конце) и truncated. Прежний вызов с одним scope работает, выдаёт первую страницу с явным остатком; документацию и старые ожидания полного списка обновить там, где это следствие контракта.
- Каждая запись содержит key, краткие label/category/description и прежние фактические value/type/unit/options/enabled/settable/границы/limitations. Описание из подтверждённого Definition API или небольшого каталога, статическое происхождение текста отделить от runtime-значений. Нет описания — не выдумывать. Ограничить description, например500 символов; оценить размер options/полного ответа.
- Фильтры/пагинация применяются ДО runtime-чтения метаданных; Qt читает только выбранную страницу. Список категорий можно кратко вернуть в результате/схеме, отдельный многошаговый каталог не нужен.
- MCP и LLM используют тот же каталог/схемы/валидацию. Обновить capabilities/безопасную validation-диагностику, если требуется. Не ослаблять отказ до native-вызова.

Если конкретная деталь требует иного контракта — короткое обоснование ведущему ДО реализации. Новый визуальный редактор120 полей не нужен: задача про инструменты и понятную адресную выдачу в существующем чате.
