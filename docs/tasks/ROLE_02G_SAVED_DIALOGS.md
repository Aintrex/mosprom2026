## Граница MVP

- Простое локальное версионированное JSON-хранилище в пользовательской области плагина через API выданного STE. Runtime путь получить штатно в Qt и передать обычной строкой worker, не хардкодить путь этой машины. Никаких облаков, БД, embeddings или дополнительногоLLM ради суммаризации.
- Хранить сообщения, безопасные результаты и необходимый ограниченный контекст выбранного диалога; небольшой список диалогов с названием/датой в существующем UI и переключение для продолжения. Сохранять новый формат сообщений/ошибок/JSONdetails. Предусмотреть понятную ошибку недоступного/повреждённого хранилища, не уничтожать файл молча.
- Ограничить объём/число записей, валидировать входные файлы, писать атомарно (временный файл→os.replace). ФайловоеIO не выполнять в Qt/под ServiceLock; без универсальной системы хранения. Механизм согласовать до кода. История должна пережить нормальное закрытие/повторное открытие; незавершённые ходы отметить прерванными, не выполнять заново.
- Не сохранять ключ/Preferences/headers/сырые запросы провайдера/base64/байты вложений/произвольные локальные пути/служебные процессные ссылки. Прежняя санитизация обязательна. Переписка остаётся локальной; в модель отправляется ограниченный контекст только выбранного разговора.
- После рестарта старые object_id/slice_id/export_id/file_id/download_url не являются действующими. Не восстанавливать ownership/worker/nativeоперации и не повторять tools. Артефакты/статусы явно исторические/неактуальные; вложения не обещать доступными без повторной загрузки.
- Служебные _attachment_ids старой llm-history не должны ломать следующий запрос попыткой прочитать удалённый FileStore. Нельзя оставлять orphan tool results без corresponding assistant tool_calls; сохранять целые ограниченные блоки либо предложить простой безопасный текстовый исторический контекст, чётко отделённый от актуальной сцены.
- Память диалога не заменяет чтение текущей машины/материала/сцены перед изменением. История — данные, не новые системные команды; после перезапуска обязательна проверка актуального состояния. Языковая модель не дообучается.
- Список/открытие/очистка истории, если нужен новый HTTP-маршрут, документировать в API_CONTRACT; активный/pending диалог не переключать/не удалять с повтором действий. Сохранить Host/Origin/пределы/идемпотентность/restore410/дедупликацию. Разрешать только собственные непрозрачные IDs, не принимать произвольные пути.

## Компактный интерфейс по уточнению пользователя

- Список названий и дат разговоров, заметное выделение текущего, «Новый диалог», открытие выбранного и удаление с подтверждением. Название из первых слов сообщения без дополнительногоLLM. Не вводить обязательные формы/экран настроек ради начала разговора.
- На узком экране список сворачивается и не отнимает место у чата; достаточно простого details/select или другого малого элемента в существующей SPA. Клавиатура/Tab/видимый фокус и понятные подписи, длинные названия переносятся, нет горизонтального переполнения на360/1024/1440.
- Сохранить принятый DOM-Markdown/человеческие ошибки/закрытые JSONdetails/вложения/прогресс/скачивание. Новая frontend-сборка, библиотеки, дизайн-система и большой редизайн не нужны.
- Показать пустой список, загрузку, ошибку чтения/записи, неполную историю и исторические вложения. «Сохранено» только после подтверждённой записи. При недоступном хранилище можно явно работать временно, но не обещать восстановление после закрытия.
- Переключение/удаление не повторяет POST сообщения, не запускает tools и не восстанавливает сцену. Заблокировать операции при LLM/pending; удаление разговора с ещё наблюдаемой собственной slice/export не должно оставлять worker с отсутствующим session. Удаление истории не отменяет engine и не удаляет пользовательский3MF/G-code.

## Особенности записи и восстановления для технического плана

- _finish освобождает active-turn и следующий запрос может обогнать запись старого снимка: нужны монотонные revisions и последовательная запись/проверка свежести. Удалённый разговор не должен воскреснуть от запоздалого snapshot/finish. FileStore/Prefs/native-вызовы не выполнять под ServiceLock.
- Shutdown Extension вызывается вQt: не join дисковогоworker наQt радиflush. Важно сохранять принятый запрос/завершённый ход до обещания сохранения; прерванный ход после рестарта помечать, не повторять. Короткий конкретный механизм согласовать, не строить универсальную очередь задач.
- После рестарта непрозрачный model-1 может снова принадлежать ДРУГОМУ объекту. Одной надписи «исторический» недостаточно, если rawtoolаргументы со старымID опять становятся командами: исключить старые operationalIDs из действующего LLM-контекста/прав. Безопасный текстовый исторический контекст допустим по согласованию; не обещать сохранение точного tool-протокола, если выбран такой вариант.
- Известный ключ санитизируется и в пользовательском тексте. Не добавлять новую систему классификации любых секретов; сохранять только нужные явно отобранные поля и не сериализовать весьservice/Preferences/rawrequest.

## Приёмочный сценарий

На временном тестовом каталоге создать разговор→завершить turn→пересоздать service/store→найти/открыть тот же разговор→следующий запрос видит предыдущий контекст, при этом старые инструменты не выполнялись и nativeIDs/загрузки не ожили. Отдельно проверить прерванный turn/pending, повреждение/ошибку записи, атомарность/размеры, отсутствие секретов/base64 и истёкшие вложения. JS — переключение/восстановление/ошибки без повторного POST; новый красивый фронт сохранить. Подмены не заменяют реальную STE-приёмку.
