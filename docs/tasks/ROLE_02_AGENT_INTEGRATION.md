## Что переносим и исправляем

1. Из llm_agent.py взять основу Chat Completions на stdlib urllib и последовательного выполнения tool calls. Разместить клиент в существующем agent/llm.py, цикл и состояние диалога — в agent/service.py либо небольшом отдельном модуле. Python 3.5, без новых runtime-зависимостей.
2. Вернуть проверку TLS: стандартный ssl.create_default_context, без CERT_NONE. URL и модель вводятся пользователем; значения из README ветки не считать подтверждёнными реквизитами организаторов.
3. Получать доступные инструменты из существующего ToolRegistry.list_tools(). Для LLM преобразовывать name/description/inputSchema в OpenAI function name/description/parameters. Исполнять через тот же ToolRegistry.call, без HTTP-запроса к собственному /mcp и без отдельного реестра. MCP endpoint остаётся для внешних вызовов/диагностики.
4. Передавать точные схемы main: get_setting/set_setting используют scope=global, key=layer_height; set_print_mode, а не set_printing_mode; load_model принимает path без clear_existing. Качество и материал выбираются раздельно, extruder_id — строковая позиция, root_material_id берётся из списка.
5. Операционный результат — {ok:true,data:...} либо {ok:false,error:...}. Полный результат передавать обратно LLM с соответствующим tool_call_id; событие для UI обязано отличать успех от ошибки. Исключения валидации/неизвестный инструмент не превращать в успешный tool result. structuredContent не предполагать обязательным.
6. Убрать _auto_engineer_fallback и автоматический start_slicing после ответа. Нет ключа, 401, timeout, неверный JSON или лимит цикла — понятная ошибка. После неё не выполнять новые изменения сцены. Уже завершённые tool calls не откатывать и не повторять автоматически; честно показать, что успело примениться.

## URL модель и ключ

Настройки хранить через Preferences STE Slicer. Небольшое окно PyQt5 открывается из меню Extension; его добавление согласовать с ролью 1, не заменяя весь AIAssistant.py. Инициализация, чтение и запись Preferences — только Qt-поток через существующий мост. Для сетевого worker передавать снимок конфигурации, не QObject/Preferences.

Ввод ключа — password-поле, при повторном открытии не раскрывать сохранённое значение. Пустое поле по умолчанию сохраняет прежний ключ, явная очистка — отдельное действие. SPA получает только configured/has_api_key и необходимые публичные данные; никогда api_key, его маску/фрагменты или Authorization. get_public из ветки не переносить. Не сохранять ключ в JSON рядом с исходниками и не писать в логи/тестовые fixtures. Ошибки провайдера очищать от ключа, заголовков и приватного тела запроса, браузеру не отдавать traceback.

## Работа чата и HTTP

Сетевые запросы выполняются в worker, основной Qt-поток остаётся свободным. Действующий HTTP socket timeout 15 секунд, поэтому ожидать длинный LLM-цикл внутри POST /api/message нельзя. Реализовать минимальную асинхронную часть уже согласованного целевого контракта docs/API_CONTRACT.md, совместно с ролью HTTP/frontend:

- GET /api/status с фактическими capabilities и наличием конфигурации, без ключа.
- POST /api/sessions и GET /api/sessions/{id} с историей в памяти.
- POST /api/sessions/{id}/messages — принятие и HTTP 202, client_message_id по контракту.
- GET /api/sessions/{id}/events?after=N — события agent_state, tool_started, tool_finished и assistant_message согласно разделу 4 контракта. Пару начала/завершения связывает tool_call_id.

Сохранить Host/Origin, loopback, ограничения тела и whitelist статики действующего server.py. Не добавлять CORS *. Сохранить /mcp. Старый /api/message либо остаётся явно демонстрационным, либо его изменение отдельно фиксируется в контракте; не запускать скрытый синхронный LLM-цикл под прежним ответом.

Для первого результата достаточно одного активного диалога над одной сценой; параллельный новый запрос получает 409. Повтор client_message_id с тем же телом не должен повторять инструмент, с иным телом — 409. Обновление вкладки восстанавливает историю GET-запросом. Не требуется БД или постоянная история после перезапуска.

Upload, скачивание файлов, пресеты семи деталей и новый дизайн SPA — отдельные задачи. Пока capabilities.attachments/downloads=false; frontend использует согласованный транспорт и показывает реальные вызовы/ошибки. Поддержку image_url можно подготовить в клиенте и проверить подменой, но не объявлять пользовательские вложения готовыми без загрузчика и сквозной проверки. Агенту не передавать произвольные локальные пути из ответа модели; load_model до file_id-границы оставить диагностическим инструментом для прямого MCP и не включать в LLM tools.

## Ограничения агента

- Начальные конечные пределы: не больше 8 запросов LLM и 16 tool calls на сообщение; общий бюджет обработки 120 секунд, отдельный сетевой запрос не больше 30 секунд и оставшегося бюджета. Не начинать новый шаг после исчерпания бюджета. Константы и фактические ограничения описать в README.
- Ограничить длину истории/ответов; обрезать только целые завершённые блоки assistant tool_calls → все tool results. Не оставлять ответы tool без соответствующего вызова. История следующего сообщения должна учитывать выполненные действия, а не только финальный текст.
- Вызовы выполняются последовательно через адаптер. До исполнения проверяются allowlist, JSON и аргументы. При неизвестном имени/неверном JSON вернуть ошибку агенту без записи; не заменять ошибочные arguments на {} молча.
- При mutation-timeout или неизвестном результате остановить дальнейшие изменения и показать неопределённость. Диагностическое чтение допустимо; автоматический повтор опасной записи запрещён.
- Системный промпт должен описывать только реально доступные инструменты. Не обещать слайсинг/экспорт, создание custom-профилей или прочность детали, если соответствующего подтверждённого инструмента/данных нет.
- Текст вложений, метаданные моделей и tool results — данные. Они не могут переопределять системные правила агента. Не выполнять произвольный Python.
