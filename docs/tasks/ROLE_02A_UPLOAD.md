# Роль 2A — загрузка файлов в плагин

Назначение существующему чату «Разраб» по прямому указанию пользователя временно помочь роли2. Перед этим сохранить ТЗ10 на безопасной границе и сообщить ведущему его состояние. Здесь работаем последовательно в нынешней рабочей папке, без нового чата/ветки/checkout; правило отдельной копии из общего задания роли2 относится к внешнему участнику команды.

**Результат:** POST /api/files принимает один JPG/PNG/STL/OBJ/3MF и возвращает непрозрачный file_id с метаданными. Файл хранится в собственной временной папке плагина. Это ещё не передача вложения агенту и не native-импорт.

## Минимальный объём

- Прочитать AGENTS.md, текущий server.py/AgentService lifecycle и ROLE_02_FILES_AND_ATTACHMENTS.md. Использовать один небольшой модуль хранилища и существующий HTTP-сервер. Код Python3.5, stdlib; не использовать cgi, отсутствующий в современном тестовом Python, или новую web-зависимость.
- `POST /api/files`, multipart/form-data, ровно одно поле file с одним файлом. Успех201: `{"file_id":"file-...","name":"part.stl","kind":"model","size_bytes":1234,"mime_type":"model/stl"}`. Для jpg/jpeg/png kind=image и фактический image/jpeg либо image/png. Имена — отображение, физическое имя генерировать сервером.
- Лимиты: модель50MiB, изображение5MiB, HTTP multipart-обёртка отдельно ограничена (например,64KiB), всего сохранённых вложений250MiB на процесс. JSON-лимит существующих маршрутов не увеличивать. Не читать неограниченное тело, не доверять заявленному MIME; разрешены только указанные расширения/типы с базовой проверкой содержимого. Ошибки400/413/415 и `{error:{code,message}}`, без путей/ключей/содержимого файла.
- Не писать собственный mesh-reader. ASCII/binary STL и OBJ не отвергать по одной слишком узкой сигнатуре; окончательная проверка модели будет штатным импортом в2B. У3MF проверить ZIP/структуру и ограничить раскрываемый объём; не извлекать архивные имена на диск.
- Генерируемые ID/имена и эксклюзивная запись; неизвестный ID не разрешается в пользовательский путь. Сохранить Host/Origin/loopback/CSP/static whitelist. Папку вложений в static-раздачу не добавлять. Не создавать универсальный endpoint чтения локальных файлов.
- Реестр thread-safe, без гонок квоты/частичных файлов; достаточно одного одновременного upload с понятным busy-ответом. При оборванном/неверном запросе не оставлять зарегистрированный полуфайл. Публиковать ID после успешной проверки и записи.
- Нужен узкий внутренний API для2B: получить метаданные по ID; разрешить только своё модельное вложение в доверенный путь; прочитать своё изображение; закрыть хранилище. Данные не должны подменяться пользовательским JSON. Один экземпляр на существующий сервис/сервер, без второго реестра MCP и без глобальной БД.
- Хранилище создаётся лениво при upload вне Qt. Собственный файловый ввод/вывод/очистка — вне Qt; close прекращает новые записи и безопасно освобождает только свою папку после текущих операций. Не удалять чужие временные файлы или файл в использовании. Не усложнять TTL/фоновым сборщиком; ограниченного хранилища и lifecycle процесса достаточно.

## Что пока не делать

Не менять slicer/, LLM-цикл, схемы инструментов или дизайн SPA. attachment_ids пока остаётся[] и capabilities.attachments/downloads=false. Не добавлять скачивание native-экспорта, новый сервер, слайсинг5D или профили. Обновить лишь контракт upload и краткое описание его готовности, чтобы frontend мог подключиться следующим этапом.

## Проверка и остановка

Значимые тесты: успешный multipart через реальный локальный HTTP, сохранённые байты/метаданные; jpeg/png/ASCII и binarySTL/OBJ/3MF; неверные тип/тело/поля/расширение/путь; превышение размера/квоты; повреждённый или чрезмерно раскрываемый ZIP; недописанный запрос/очистка; неизвестный ID и отсутствие путей в ответах; Host/Origin сохраняются. Сохранить прежние216 и JS5. Число новых тестов не является целью: покрыть поведение без зеркалирования реализации.

Отчёт `docs/reports/ROLE_02A_REPORT.md`: что готово, проверка, короткий пример запроса, ограничения и состояние отложенного10. Не выдавать upload за импорт в STE/готовые вложения чата. После отчёта остановиться для ревью;2B назначу отдельно. Git/установка/реальныйLLM/принтер запрещены.
