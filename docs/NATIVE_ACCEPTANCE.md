## Роль2 и frontend: сквозной прогон

Пользователь проверяет реальные URL/модель/ключ, чтение→одна запись/readback→восстановление, вложение/импорт, отдельно vision, свойslice и явныеэкспорты. Полныйсценарий — ROLE_02_ACCEPTANCE.md. В canonical с2D собственныеslice/export продолжают обновлять карточки послеidleLLM; чужие/MCP-запуски этим не наблюдаются. В296 нужны явные чтения статусов агентом. Скачивание доступно после подтверждённого native-экспорта и регистрации его агентом.

Для нового frontend проверить жирное выделение/списки/код, короткие человеческие итоги иошибки, закрытые техническиедетали, неизвестный прогресс и отделение idleLLM отработыengine. Refresh/410 восстанавливают историю/карточки без повторныхPOST/импорта/экспорта; вложения и ссылки не ломаются. Тестовые данные браузерного preview не считать реальными результатами слайсера дляпрезентации.

При timeout не повторять запись/start/import/export автоматически: сначала чтение/UI того же запуска. Сетевой отказLLM не отменяет уже выполненные изменения. observation_interrupted не означает остановкуengine. После измененияпроекта старыйdownload должен быть отклонён какstale, безавтоматическогопересоздания файла.
