До замены сохранить прежнюю копию; не копировать дистрибутив/исходники STE, ключи и временные данные в Git.

Для проверки нужны работающий STE Slicer7.10.12, профиль Hybrid530V5.2.4, выданные модели с описаниями, исправные штатные движки и разрешённая активация5D. Новый порт брать из открытого меню AI Assistant→Open chat; старые localhost-порты и ID после рестарта не действуют.

## Сначала без LLM — через MCP

Команды по каждому инструменту находятся в `plugin/README.md`; диагностический сценарий первого чекпоинта — `scripts/demo_checkpoint.ps1`. Выполнять по одному шагу, сравнивая ответ и UI, не отправлять всё одновременно.

1. **Диагностика и параметры.** Проверить health/initialize/tools/list/get_slicer_state, точную машину и backend. Прочитать настройки, изменить и восстановить layer_height; отдельно проверить явный extruder_id. Сменить три разрешённых режима и вернуть classic. Выбор backend сам по себе не доказывает нарезку.
2. **Материалы и профили.** Получить актуальные списки, выбрать доступные builtin-качество/материал и подтвердить контейнеры/UI. Создать уникальный временный custom-профиль, изменить разрешённую настройку, сохранить и выбрать его заново. После рестарта найти тот же ID и значения; `disk_verified` в прежнем процессе не заменяет эту проверку. Временный профиль удалять штатным UI после сохранения нужных результатов.
3. **Сцена.** Импортировать небольшую реальную модель и дождаться своего fileCompleted/объектов. Проверить ID/габариты; при выключенной физике — перемещение/поворот/масштаб/Undo и удаление временной копии. Авторасстановка поддержана в classic; её completed не доказывает отсутствие всех коллизий, all_fit может быть null.
4. **Настоящий результат.** Auto-slice выключен, preview закрыт. Запустить один slicing, сохранить slice_id и читать статус до фактического completed/valid. Сверить время/материал с UI. Затем отдельно запустить native G-code и workspace3MF, дождаться completed экспорта. Timeout не отменяет engine/writer: перечитать состояние/UI, не повторять запуск автоматически.
5. **Проверка файлов.** Открыть G-code в Preview, 3MF повторно как проект/workspace. Подтвердить машину, режим, материал, профиль, важные настройки, ориентацию/позицию/геометрию. Повторить сквозной сценарий для двух5D и всех выданных моделей по их задачам. Лицензию/отсутствующий engine/неподходящую геометрию фиксировать как блокер, не обходить и не выдавать за успешный тест.

## Затем отдельный прогон чата с реальным LLM

Только после отдельного разрешения и ввода URL/модели/ключа пользователем в Qt→LLM Settings. Ключ в чат/документы/скриншоты не добавлять. Проверить: фото действительно передаётся как image_url; приложенная STL/OBJ/3MF загружается по file_id; действия/ошибки видны; настройки и режим подтверждаются native-результатами.

Дождаться завершённого экспорта и попросить агента прочитать get_export_status по своему export_id. Именно это наблюдение регистрирует download_url и карточку; прямой MCP-вызов не создаёт карточку чата. Скачать оба файла, сравнить с native-экспортом, проверить Preview/reopen. Refresh/повтор статуса не должен дублировать импорт/экспорт/карточки. При изменении проекта старая ссылка получает stale409, новый экспорт незаметно не запускается. Engine может продолжаться после ответа агента: отображаемый progress — последний tool-снимок, фонового наблюдения пока нет.

## Что сохранить после проверки

Короткий runtime-протокол: версия/машина/режим, модель и задача, выполненные шаги, фактические исходы, ошибки и ограничения. Сохранять реальные `results/<model_name>/project.3mf`, `result.gcode`, `chat_*.png` только после проверки; пустых placeholder-файлов не создавать. Отдельно отметить провайдера/vision и рестарт профиля. Старый тестовый G-code/подменный writer не является результатом для жюри.

Публикация изменений08+, интеграция нового frontend и отправка архива выполняются только в отдельно разрешённом объёме. Текущие commit/push и установка не были выполнены.
