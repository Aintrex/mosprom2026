# Первый чекпоинт: текст и сценарий показа

Подготовлено 23 октября 2026 года по текущему репозиторию. Это отчёт о нашей интеграции; готовность frontend и LLM у других участников нужно согласовать с ними. Длительность ниже — предложение для репетиции, не регламент организаторов.

## Текст выступления, около двух минут

Мы делаем интеллектуального помощника для STE Slicer. Пользователю сложно разобраться в большом количестве настроек печати. Наша цель — дать ему возможность описать задачу обычными словами и приложить модель, а затем получить подготовленный проект, G-code и объяснение выбранных параметров.

Например, человек пишет: «Кронштейн под нагрузку, PETG, без поддержек». В готовом решении помощник должен выбрать материал, профиль и режим, подготовить модель и запустить слайсинг. Сейчас этот полный сценарий ещё в разработке.

На первом этапе мы сосредоточились на управлении самим STE Slicer. Плагин уже запускается внутри приложения и открывает интерфейс в браузере. Подготовлены команды чтения и изменения высоты слоя, диагностики принтера и переключения трёх разрешённых режимов: 3D, 5D Spiral и 5D. Высоту слоя и режимы мы уже проверили в установленной сборке на Stereotech Hybrid 530 V5.2.4.

Следом мы реализовали список и выбор качества и материалов, а также импорт STL, OBJ и 3MF. Загруженные модели получают идентификаторы; можно прочитать их реальные размеры. Эти новые функции прошли автоматические проверки и ожидают ручной приёмки в слайсере. Всего сейчас проходит 94 автоматических теста.

Наш основной технический результат — команды обращаются к реальному API приложения, проверяют полученное состояние и возвращают понятные ошибки. Работа с приложением передаётся в его основной поток. При импорте мы ждём появления моделей, а не выдаём запуск операции за готовый результат.

Сейчас покажем проверенное изменение высоты слоя и переключение режимов. Через технический интерфейс вызываются те же инструменты, которые позже будет выбирать ИИ. Подключение LLM и его ключа пока не реализовано; чат в этой версии демонстрационный.

Дальше мы завершаем ручную проверку моделей и профилей, добавляем настоящий слайсинг и сохранение файлов, затем объединяем это с агентом и frontend. Главный критерий следующего результата — получить настоящий 3MF и G-code из слайсера.

Если загрузка уже успешно отрепетирована, перед показом детали можно добавить: «На этой сборке мы также проверили загрузку данной модели: сейчас покажем её появление на столе и чтение габаритов». Без такого прогона эту фразу не использовать.

## Что подготовить заранее

1. Сохранить открытый проект и закрыть STE Slicer. Сделать резервную копию установленного AIAssistant вне папки plugins.
2. Обновить **весь** каталог плагина, включая slicer/models.py и slicer/profiles.py. Только открытие страницы в старом браузере не обновляет Python-код.
3. Запустить STE Slicer 7.10.12, выбрать **Stereotech Hybrid 530 V5.2.4**, **3D**, пустую сцену. Закончить текущие операции, выйти из G-code preview.
4. Открыть **Extensions → AI Assistant → Open chat**. Записать порт из нового адреса http://127.0.0.1:ПОРТ/. После перезапуска он может измениться.
5. Держать рядом окно слайсера с настройками Quality / Printing Mode и PowerShell. Для нового импорта подготовить небольшой знакомый STL до 50 MiB и сначала пройти сценарий без зрителей.

Каталог установки уточнить через **Справка → Показать папку конфигурации**. На этой машине использовался %APPDATA%\steslicer\7.10\plugins. Если это по-прежнему верный каталог, обновить его можно следующими командами **при закрытом слайсере**, после резервной копии:

```powershell
Set-Location 'C:\Users\sevay\Documents\ChatGPT\hackaton_2026'
$demoPluginsDir = Join-Path $env:APPDATA 'steslicer\7.10\plugins'
if (-not (Test-Path -LiteralPath $demoPluginsDir -PathType Container)) {
    throw 'Уточните папку plugins через меню STE Slicer'
}
Copy-Item -LiteralPath '.\plugin\AIAssistant' -Destination $demoPluginsDir -Recurse -Force
```

Затем запустить приложение обычным ярлыком. Отдельный Python, pip install или dev_server.py для показа интеграции не нужны. Команда python scripts/dev_server.py запускает только каркас без подключения к слайсеру и не подходит для демонстрации изменения его настроек.

## Подключение PowerShell

Этот блок выполнить один раз в текущем окне PowerShell, после открытия чата. Ввести только номер порта. Здесь явно используется UTF-8, чтобы пути с русскими буквами передавались правильно.

```powershell
$demoPort = [int](Read-Host 'Порт из нового адреса чата')
$demoBase = 'http://127.0.0.1:{0}' -f $demoPort
$demoMcp = $demoBase + '/mcp'
$script:demoRpcId = 0

function Invoke-DemoRpc {
    param([string]$Method, [hashtable]$Params = @{})
    $script:demoRpcId += 1
    $json = @{jsonrpc='2.0'; id=$script:demoRpcId; method=$Method; params=$Params} |
        ConvertTo-Json -Depth 25 -Compress
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
    $reply = Invoke-RestMethod -Uri $demoMcp -Method Post -TimeoutSec 35 `
        -ContentType 'application/json; charset=utf-8' -Body $bytes
    if ($null -ne $reply.error) {
        throw ($reply.error | ConvertTo-Json -Depth 15 -Compress)
    }
    return $reply
}

function Invoke-DemoTool {
    param([string]$Name, [hashtable]$Arguments = @{})
    $reply = Invoke-DemoRpc 'tools/call' @{name=$Name; arguments=$Arguments}
    $value = $reply.result.content[0].text | ConvertFrom-Json
    if ($reply.result.isError -or -not $value.ok) {
        throw ($value | ConvertTo-Json -Depth 25 -Compress)
    }
    return $value.data
}

Invoke-RestMethod -Uri ($demoBase + '/api/health')
Invoke-DemoRpc 'initialize' @{} | ConvertTo-Json -Depth 15
(Invoke-DemoRpc 'tools/list' @{}).result.tools | Select-Object name
Invoke-DemoTool 'get_slicer_state' @{} | ConvertTo-Json -Depth 15
```

Ожидается реальная машина Hybrid 530 V5.2.4, printing_mode=classic и backend.matches_mode=true. Если нового load_model нет в списке инструментов, установлена старая копия плагина: исправить установку и перезапустить, не продолжать показ новой функции.

## Основной показ, две-три минуты

### 1. Высота слоя: команда меняет настоящее приложение

В STE Slicer раскрыть Quality. Выполнять блоки последовательно, сверяя окно после каждого изменения:

```powershell
$demoLayerBefore = Invoke-DemoTool 'get_setting' @{key='layer_height'; scope='global'}
$demoLayerBefore | ConvertTo-Json
$demoLayerTarget = if ($demoLayerBefore.value -eq 0.12) { 0.1 } else { 0.12 }
Invoke-DemoTool 'set_setting' @{key='layer_height'; scope='global'; value=$demoLayerTarget} |
    ConvertTo-Json
```

Показать изменившееся поле. Сказать: «Это фактическое значение в слайсере. Команда проверяет результат после записи». Затем восстановить исходное значение и убедиться в UI:

```powershell
Invoke-DemoTool 'set_setting' @{key='layer_height'; scope='global'; value=$demoLayerBefore.value} |
    ConvertTo-Json
```

### 2. Три режима: проверить настройку и обработчик

Пока сцена пустая, раскрыть Printing Mode. Выполнить первую команду, показать UI и matches_mode=true в ответе, затем следующую:

```powershell
Invoke-DemoTool 'set_print_mode' @{mode='cylindrical'} | ConvertTo-Json -Depth 15
```

```powershell
Invoke-DemoTool 'set_print_mode' @{mode='cylindrical_full'} | ConvertTo-Json -Depth 15
```

```powershell
Invoke-DemoTool 'set_print_mode' @{mode='classic'} | ConvertTo-Json -Depth 15
```

Сказать: «Поддержаны три режима из задания. Здесь мы подтверждаем переключение; нарезку в 5D пока не демонстрируем».

### 3. Загрузка модели: только после успешной репетиции

Теперь, в режиме classic, импортировать подготовленную деталь. Ввести абсолютный путь к STL **без окружающих кавычек**. Чат пока не принимает вложения, поэтому используем техническую команду.

```powershell
$demoModelPath = Read-Host 'Абсолютный путь к небольшому STL'
$demoLoaded = Invoke-DemoTool 'load_model' @{path=$demoModelPath}
$demoLoaded | ConvertTo-Json -Depth 20
Invoke-DemoTool 'list_models' @{} | ConvertTo-Json -Depth 20
foreach ($item in $demoLoaded.objects) {
    Invoke-DemoTool 'get_model_bounds' @{object_id=$item.object_id} | ConvertTo-Json -Depth 20
}
```

Показать деталь на столе, её ID и bounds.size. Объяснить: «Импорт завершился, модель появилась. Дальнейшие команды смогут обращаться к ней по ID. Размеры в миллиметрах, во внутренних осях слайсера Y означает высоту».

Для репетиции OBJ и 3MF есть полный порядок в [plugin/README.md](../plugin/README.md). Для короткого выступления достаточно одного заранее проверенного файла. В 3MF здесь импортируется геометрия с возможными настройками объектов, а не восстанавливается весь проект.

## Если осталось время и как закончить

Можно **прочитать** список качества и материалов, не меняя их во время короткого показа:

```powershell
Invoke-DemoTool 'list_quality_profiles' @{} | ConvertTo-Json -Depth 20
Invoke-DemoTool 'list_materials' @{extruder_id='0'} | ConvertTo-Json -Depth 20
```

Выбор материала и качества пока не прошёл ручную приёмку. Для живого показа его сначала нужно отдельно проверить с фиксацией исходных настроек и восстановлением; не выбирать наугад ID из примера.

В завершение показать ближайшие работы: ручная приёмка новых инструментов → реальный слайсинг → проект/G-code → объединение с LLM и frontend. Сохранить скриншоты реальных результатов. Тестовую деталь затем удалить штатным UI; режим вернуть в classic, высоту слоя — в исходное значение.

## Если показ не идёт

- Нет связи: проверить, что запущен именно STE Slicer, открыт пункт Open chat и указан текущий порт.
- slicer_not_connected: вероятно, подключились к dev_server, а не плагину приложения.
- Таймаут импорта: вызвать list_models и посмотреть сцену. **Не повторять load_model автоматически** — предыдущий job может ещё завершиться. При удерживаемой блокировке без завершения сохранить работу и перезапустить приложение.
- Не проходит новая функция: остановить её показ и вернуться к подтверждённому сценарию высоты/режимов. Можно открыть настоящие скриншоты [приёмки ТЗ 02](reports/TASK_02_RUNTIME.md), прямо назвав их записью предыдущего прогона.

Не заявлять подключённый ИИ, автоматический подбор режима по тексту, готовый G-code или завершённую проверку всех форматов, пока это не выполнено. На вопрос «где нейросеть?» ответ: «На этом этапе готовим проверяемые инструменты управления слайсером. Подключение LLM — следующий интеграционный шаг; сейчас команды вызываем напрямую».
