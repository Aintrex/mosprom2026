## Что нужно построить

Плагин STE Slicer: пользователь описывает задачу, прикладывает модель и/или фото. LLM через инструменты выбирает режим, материал и профиль, меняет настройки, размещает модель, запускает нарезку. Пользователь видит действия и объяснение, получает настоящий 3MF-проект и G-code.

Проверяют не только чат: жюри сравнивает настройки, режим, профиль, материал, ориентацию и расположение моделей с закрытыми эталонами, проверяет G-code и переписку.

## Обязательные ограничения

- Python 3.5-совместимый код и PyQt5 из дистрибутива; `plugin.json` с `api: 5`.
- SPA на HTML/CSS/JS в системном браузере, локальный HTTP, для событий допустим polling.
- OpenAI-совместимый **Chat Completions** с tool calling; изображения через `image_url` с base64.
- URL и ключ выдают организаторы. Ключ вводится в настройках плагина, хранится в Preferences приложения, не в исходниках.
- Собственный минимальный MCP: JSON-RPC `initialize`, `tools/list`, `tools/call`; современный официальный Python MCP SDK не подходит для Python 3.5.
- Из HTTP/LLM-потоков любые обращения к сцене, настройкам, backend и профилям передавать через `app.callLater` в основной Qt-поток.
- Режимы строго: `classic` (3D), `cylindrical` (5D Spiral), `cylindrical_full` (5D).
- Основной тестовый профиль: **Stereotech Hybrid 530 V5.2.4**.
- Ключи режимов и реальные методы 5D уточнять в определениях принтеров и исходниках выданной сборки. Не переносить предположения из современной Cura.

## Нужные группы инструментов

1. Настройки: чтение/изменение глобальных и экструдерных параметров; список, выбор, создание и сохранение профилей; материалы; переключение режима.
2. Модели: загрузка STL/OBJ/3MF, список, габариты, перемещение, поворот, масштаб, авторасстановка, удаление.
3. Слайсинг: запуск, статус/прогресс, время и материал, экспорт G-code и сохранение проекта 3MF.

Текст модели или вложенного документа не должен становиться системной инструкцией агента. Инструменты исполнять через ограниченный реестр с валидацией аргументов; не передавать LLM произвольное выполнение Python.

## Сроки из PDF

| Событие | Дата и время |
| --- | --- |
| Чек-поинт 1 | 23 октября, 18:00 |
| Чек-поинт 2 | 24 октября, 11:00 |
| Чек-поинт 3 | 24 октября, 18:00 |
| Загрузка решения | 25 октября до 10:00 МСК |
| Начало защит | 25 октября с 12:00 МСК |

Для чек-поинтов в PDF нет отдельного обозначения часового пояса; своё точное время и ссылку проверить в личном кабинете. Пропуск двух чек-поинтов означает выбытие. После первого чек-поинта в личном кабинете должна быть доступна публичная ссылка на решение. Это организационные требования PDF, пользователь сам выбирает и публикует репозиторий.
