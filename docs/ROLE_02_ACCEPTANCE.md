## 1. Только чтение

```text
Проверь подключение к STE Slicer только чтением: вызови get_slicer_state, list_models и get_setting для layer_height со scope=global. Сообщи фактические машину, режим, backend, количество объектов и высоту слоя из результатов. Ничего не меняй, не запускай нарезку и не запрашивай ключ или Preferences. Если чтение недоступно, покажи реальную ошибку.
```

Ожидание: три настоящих инструмента и их результаты в ленте, соответствующие UI; нет mutating tools. Dev возвращает slicer_not_connected, а не вымышленную машину. Даже заполненные настройки LLM не доказывают связь до фактического ответа провайдера.

## 2. Изменение слоя → readback → восстановление

```text
На свободной тестовой сцене сначала прочитай исходный layer_height через get_setting scope=global и сохрани его значение для восстановления в этом ходе. Затем установи 0.24 мм, а если исходное значение уже 0.24 — 0.20 мм, через set_setting. Перечитай get_setting и покажи фактическое значение. Только после подтверждённого успеха верни исходное значение через set_setting и снова прочитай get_setting. Другие настройки не меняй. При любом отказе или неподтверждённой записи остановись, сообщи последнюю подтверждённую фазу; автоматически повторять запись или откатывать неизвестный результат нельзя.
```

Ожидание: предварительное describe_settings согласно инструкциям агента, затем get→set→get→set(original)→get, реальные before/after и исходное значение в финале. Сверить UI. Во время engine/import/export возможен busy: сцена не должна меняться; не продолжать цепочку после отказа. Если восстановление не подтверждено, пользователь сверяет UI и возвращает слой вручную. Прежний slice после изменения остаётся stale даже при восстановлении значения.

## 3. Вложение и настоящий импорт

Прикрепить **один небольшой известный STL/OBJ/3MF** через picker; дождаться успешного upload. Для отдельной проверки vision в этом же сценарии можно приложить JPG/PNG; содержание изображения должно быть известно пользователю. Не повторять импорт в ту же сцену из-за задержанного ответа.

```text
Импортируй только приложенную модель через load_model_file по её file_id, без локальных путей и повторного импорта. После подтверждения прочитай list_models и габариты нового объекта через get_model_bounds по полученному object_id. Покажи фактические ID и размеры в мм. Если приложено изображение, отдельно опиши видимое на нём, не выдавая изображение за измерение геометрии. Настройки не меняй, нарезку и экспорт не запускай. При ошибке/неопределённом импорте остановись и предложи проверить список объектов/UI без повторной загрузки.
```

Ожидание: upload-ID/имя восстанавливаются после refresh; load_model_file с подтверждёнными objects, затем чтения; новая модель и её габариты видны в STE. Upload201, message202 или ответ LLM сами импорт не доказывают. Для фото нужен реальный vision-provider: отказ не заменяется выдуманным анализом. Unknown ID/wrong kind/model_load_timeout остаются ошибками; после timeout reader мог продолжиться. Ручная приёмка ТЗ03/04 автоматически этим текстом не закрывается.

## 4. Своя classic-нарезка

После подтверждённого импорта, на подготовленной classic-сцене:

```text
Прочитай get_slicer_state и list_models. Если фактический режим classic, backend ему соответствует и модель есть, запусти start_slicing ровно один раз; иначе остановись и объясни фактическое ограничение, ничего не переключая. Сообщи возвращённый slice_id и состояние. Если queued/running — честно скажи, что операция ещё идёт, и заверши ответ без серии опросов или раннего get_slicing_result. Не запускай экспорт и не повторяй start. Автообновление обещай только если оно доступно в этой версии плагина.
```

Canonical: после idle без нового сообщения карточка меняется running→completed/failed; результат/оценки времени и материала появляются только после get_slicing_result observer, без фальшивых tool-карточек/новых LLM-запросов. Сверить время/расход с STE; проверку скачанных файлов в Preview/reopen оставить до получения обоих экспортов, чтобы не потерять актуальность slice. Невалидный/failed/observation_interrupted не считать готовностью: ошибки чтения не означают остановку engine; timeout не отменяет его. Параллельный start/изменение сцены не выполнять. На296 нужны отдельные явные чтения статуса по ID, затем результата при completed/valid; отсутствие фонового обновления там ожидаемо.

## 5. Экспорты отдельными запросами

Только после подтверждённого актуального completed slice. Подставить его настоящий ID, сначала проверить G-code:

```text
Для актуального завершённого slice_id=<ВСТАВЬ_СВОЙ_ID> запусти только export_gcode ровно один раз. Сообщи export_id и фактическое состояние. Если queued/running — заверши ответ без быстрого polling; не обещай файл до подтверждённого завершения. Не запускай новую нарезку, другой экспорт или повтор writer. Если операция отклонена/результат stale, покажи реальную ошибку без обхода.
```

Canonical: после idle export_progress показывает реальное состояние, затем artifact_ready со своим download-ID/ссылкой при completed/valid. Скачать G-code; refresh не дублирует карточку. **До открытия скачанных файлов** отдельно повторить этот пятый промпт, заменив export_gcode на save_project_3mf; ID нарезки должен оставаться актуальным. Открытие файла/проекта может сделать прежний slice stale — не запускать новые writer по нему автоматически. На296 агент должен явно прочитать get_export_status до готовности/карточки; один queued не даёт файл.

Сохранить реальные ответы/ID/ошибки, скриншоты прогресса и файлы для ведущего. Послушание реальной модели, native-ввод, импорт, Preview/reopen и точность показаний подтверждаются только этим реальным прогоном, не ScriptedLLM. Физическую печать не запускать.
