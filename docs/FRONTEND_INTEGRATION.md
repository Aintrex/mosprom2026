# Клиент агентной интеграции b9c0190

Авторитетный [API_CONTRACT.md](API_CONTRACT.md) описывает границу целиком. Рабочая SPA: `plugin/AIAssistant/web/`, раздаваемые файлы — только index.html, app.js, style.css. Используйте относительные URL того же origin; сторонний localhost-порт запрещён Host/Origin. CSP допускает только локальные внешние ресурсы. Эта интеграция проверена offline; native/реальный провайдер ещё открыты.

1. `GET /api/status` → 200. `llm:{configured,has_key}` означает только заполненные подтверждённые Preferences. Не писать «подключено». URL/модель/ключ вводятся в Qt-меню AI Assistant → LLM Settings; REST-настроек/секретов нет. `agent_state` общий для сцены; capabilities.attachments=true; downloads/background_slice_events=true только в plugin (в dev оба false). Флаги описывают механизм скачивания/наблюдения своих запусков, не готовность engine/лицензии или наличие файла.
2. `POST /api/sessions` с `{}` → 201 `{session_id,messages,agent_state,last_event_id,slice,export,artifacts,tool_events}`. export=null до первого своего запуска, затем один последний свой экспорт. Сохранить session_id. После обновления вкладки `GET /api/sessions/{id}` восстанавливает обоих участников и оба статуса. Объединять messages.event_id и tool_events.id для ленты; продолжить с snapshot.last_event_id. 404 после перезапуска процесса означает потерю памяти истории, не разрешение повторить изменения.
3. Перед отправкой сохранить тело и client_message_id. `POST /api/sessions/{id}/messages` с `{"text":"Прочитай высоту слоя","client_message_id":"client-unique","attachment_ids":[]}` → 202 `{"session_id":"...","message_id":"...","client_message_id":"...","agent_state":"processing"}`. Это принятие. Один turn для всей сцены; параллельный запрос → 409 agent_busy. Одинаковые ID и принятое тело → прежний 202, изменённое тело → 409 message_id_conflict. При обрыве/5xx сохранять ID и тело, читать snapshot; повторять только явно с тем же ID. Не создавать автоматически новый ID. User брать из snapshot, не рисовать второй оптимистичный экземпляр.
4. `GET /api/events?session_id=...&after=0` → 200 `{"session_id":"...","events":[{"id":1,"type":"agent_state","created_at":"...Z","data":{"state":"processing"}}],"next_after":1,"has_more":false}`. Polling около 1 секунды, только один незавершённый запрос; при сбое backoff. События дедуплицировать по id, has_more читать сразу. 410 → snapshot и last_event_id; некорректный/будущий курсор → 400.

События для клиента:

| type | data и смысл |
| --- | --- |
| tool_started | `{turn_id,tool_call_id,name,arguments}` — проверенные аргументы |
| tool_finished | `{turn_id,tool_call_id,name,result}` — фактический `{ok,data}`/`{ok:false,error}`; возможен без started при отказе валидации |
| assistant_message | `{message_id,role,text,attachment_ids,created_at,is_error,event_id}` — финальный ответ/ошибка |
| agent_state | `{state:idle/processing}` — состояние turn, отдельно от engine |
| slice_progress / slice_finished | `{slice_id,state,progress,valid,error,observed_at,result,observation?}` — фактический снимок tool/observer, result только подтверждённый |
| export_progress | `{export_id,slice_id,kind,state,progress,valid,error,observed_at,observation}` — последний свой экспорт (kind=project/gcode), без локального пути |
| artifact_ready | `{artifact:{artifact_id,file_name,kind,size_bytes,slice_id,source,writer_id,writer_type,valid,file_id?,download_url?,download_error?}}` — полученный native-файл или обновление прежней карточки |
| error | `{code,message,related_id}` — ошибка обработки, related_id может быть null |

Карточка tool определяется парой turn_id + tool_call_id: в следующем turn тот же call ID может появиться заново. Результаты/текст выводить через textContent, никогда как HTML. Секреты не запрашивать и не хранить в SPA. Неподтверждённый результат мутации прекращает turn; не повторять инструменты на клиенте.

Если tool_finished без started содержит error.code=invalid_tool_arguments/stage=validation/executed=false, показать **«Отклонено до запуска»**, причину, arguments_summary и expected schema как текст. Не рисовать «Аргументы:null»: это раньше было начальным состоянием renderer, а не реальным payload. Новая сводка показывает только типы известных полей, обязательные пропуски/число неизвестных полей; raw значения не выдаются. Для исторического finished без started/маркера писать «Аргументы не опубликованы; запуск API не подтверждён», не приписывать доказанную отмену/отказ до API. Refresh/410 сохраняют это различие. Модель может исправить лишь marked pre-validation в прежнем ходе, UI не делает retry/POST. Ошибка после допуска к исполнению/timeout не получает executed=false и сохраняет запрет повторной мутации.

Роль2D: один ленивый worker процесса примерно раз в1с читает только подтверждённые собственные slice/export ID из успешных запусков агента. Продолжает при idle/ошибке/лимите LLM, не вызывает LLM и сам не запускает/не повторяет нарезку/экспорт. Прямой MCP и ручные UI-запуски не отслеживаются автоматически. completed slice получает оценки только после прежнего get_slicing_result; completed свой экспорт — карточку через прежний2C resolver. completed + valid:false показывать устаревшим; progress:null — неизвестная доля. Пример result: `{"slice_id":"slice-1","printing_mode":"classic","backend_id":"CuraEngineBackend","build_plate":0,"print_time_seconds":3600,"material":{"length_mm":12000,"weight_g":36},"source":"ste_slicer"}`. Это суммарные оценки STE, не собственный расчёт и не массив по экструдерам.

observation:{state:watching/finished/stopped,error:null|{code,message}} отдельно от state engine. watching — автообновление своего запуска без LLM; finished — terminal-наблюдение (успех/реальный отказ/stale); stopped+observation_interrupted — чтение прекращено с неизвестным исходом engine, не отмена. После4 ошибок backoff1/2/4с worker удаляет active-запись; последняя running/queued сохраняется. UI показывает причину отдельно от native error. Ранние slice_not_ready/qt_timeout при запросе результата агентом сами не завершают observer. Снимок без observation остаётся только диагностическим чтением. Одинаковые данные не порождают события: observed_at — время последнего изменения снимка, не heartbeat. Observer не создаёт tool_started/tool_finished; клиент не подделывает их по прогрессу.

Snapshot.export — один последний свой export/null, не массив и не история. export_progress заменяет эту карточку; pending не является artifact, готовый файл приходит только artifact_ready. Refresh/410 восстанавливает slice/export/artifacts, не запускает операции. Перед мутацией сменяется поколение, поздний ответ старого ID/владельца или до инвалидации не заменяет карточку/known stale. Подтверждённые prewrite busy-отказы (включая switch_in_progress) сохраняют наблюдение, неизвестная частичная мутация явно его прерывает. Close не ждёт Qt-worker на Qt, поздние ответы игнорируются. После terminal постоянного мониторинга внешних изменений нет; GET скачивания проверяет заново. Принятая копия tmp/acceptance/baseline_296 этого observer/export-поля не имеет и не менялась. Новая версия отдельно ожидает native-приёмки, [ROLE_02D_REPORT.md](reports/ROLE_02D_REPORT.md).

## Скачивание native-экспорта — роль2C

После выполненного агентом либо observer его собственного экспорта get_export_status с completed/valid=true отдельный resolver через QtBridge подтверждает принятый экспорт и актуальный slice. Вне Qt регистрируется стабильный download-ID; событие artifact_ready и snapshot.artifacts получают file_id и относительный download_url. Прямой MCP tools/call не регистрирует карточку чата; отдельного REST register нет. Незавершённый экспорт ссылки не получает, ошибка регистрации даёт download_error:{code,message}, без URL. Прежний upload/file_id остаётся только вложением.

Объединять карточки по artifact_id, заменять поля при обновлении (включая удаление прежней ссылки), восстанавливать массив из snapshot после refresh/410. Повторный одинаковый status не дублирует карточку. Текст имени/ошибок — textContent; href допустим только при valid===true и совпадении с `^/api/files/[A-Za-z0-9_-]{1,128}$`. Исторический артефакт без URL показать локальным результатом, известный valid=false — устаревшим без ссылки. Минимальная SPA открывает ссылку в новой вкладке с rel=noopener: Content-Disposition успешного ответа скачивает файл, JSON ошибки сохраняет основную вкладку чата.

GET `/api/files/{file_id}` без query повторно проверяет актуальность через Qt, затем открывает доверенный обычный файл вне Qt и сверяет fingerprint/размер. 200: model/3mf или application/octet-stream, Content-Length, attachment filename* UTF-8, no-store/nosniff/CSP. Не читать весь файл в JS ради кнопки: передача сервером до64KiB за блок, без ServiceLock/engine guard. До заголовков неизвестный/upload/исчезнувший ID —404, stale/изменение файла —409, закрытие/Qt недоступен —503 с {error:{code,message}}; после начала передачи возможен обрыв без JSON. Не повторять экспорт автоматически. Host/Origin остаются ограничены своим localhost-портом; пути/query не принимаются.

Известные мутации/прочитанный stale обновляют valid=false событием; фонового наблюдения за внешними изменениями нет, поэтому сервер проверяет каждый GET независимо от карточки. Уже открытая передача может завершиться после изменения сцены/close. Закрытие запрещает новые GET; очистка upload не удаляет accepted native-файлы. ID не переживают рестарт, файлы остаются в кэше STE, нужные результаты сохраняет пользователь. Fingerprint не является криптографической защитой от редактора, сохраняющего mtime. Изолированные проверки:296 Python +10 JS; native/provider/Preview/reopen остаются открыты. Отчёт — [ROLE_02C_REPORT.md](reports/ROLE_02C_REPORT.md).
