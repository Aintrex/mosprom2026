## Подтверждённый пробел и изменение

В agent/service.py SYSTEM_PROMPT по-прежнему требовал «проверяй status по возвращённому ID», а _run_turn после каждого tool возвращается к модели до лимитов8/16/120. При этом принятый _track_operation/_observe_operation уже наблюдает собственные slice/export после idle независимо от LLM. В system content не было объяснения queued/running/observer, поэтому инструкции допускали ненужный быстрый polling вместо короткого честного ответа. Это **пробел инструкций по исходникам**, а не воспроизведённый сбой реальной модели.

Изменены только инструкции в `plugin/AIAssistant/agent/service.py`: успешный queued/running → сообщить ID/незавершённость и завершить ответ; без серии быстрых status/result, повторного start/export, обещаний готового результата и автоматической цепочки slice→export. По отдельному вопросу пользователя можно прочитать текущий status один раз, result — при completed/valid. В trusted system content добавлено сведение о доступности observer из **того же признака**, что capabilities.background_slice_events (_bridge is not None): plugin объясняет автоматическое обновление лишь подтверждённого своего активного запуска, dev явно не обещает engine/observer. Чужие/исторические ID, ручные/MCP-запуски и stopped/finished не получают обещания фонового чтения; наличие bridge не гарантирует успешное завершение. observation_interrupted означает неизвестный исход, требуется чтение/UI без нового старта. Пользовательские/вложенные данные в system content не добавлялись.

Не менялись guards/лимиты/Qt/backend/engine/writers/2Dworker/реестр/HTTP/контракты/семантика выполнения tools; нового принудительного контроллера поведения нет. Это инструкция модели, не гарантия её послушания. Нельзя выдавать ScriptedLLM или тесты на строки за подтверждение реального поведения, поэтому такие тесты не добавлялись.

Добавлен [ROLE_02_ACCEPTANCE.md](../ROLE_02_ACCEPTANCE.md):5 копируемых русских промптов, последовательность read-only→слой/readback/restore→вложение/native-import→свой classic slice→по одному экспорту отдельными сообщениями. Указаны ожидаемые tools/UI/ошибки, остановка при неопределённой мутации, реальные проверки Preview/reopen, отличия canonical/296/296+UI-fix/dev. Сам прогон пользователь выполняет отдельно. Ручная приёмка ТЗ03/04 не объявлена закрытой.
