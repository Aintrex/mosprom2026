## Переданные замечания

1. Завершение turn не означает завершение engine. При background_slice_events=false интерфейс должен явно показывать последний полученный снимок, а не обещать непрерывный прогресс. Исчерпание 8 LLM-запросов не превращает продолжающийся native job в failed.
2. completed может иметь valid=false. Снимок должен сохранять актуальность; чтение статуса того же актуального slice не должно стирать ранее полученные время/расход. Требуется проверка completed → result → status → stale.
3. HTTP 5xx и обрыв связи могут оставлять принятие сообщения неопределённым. Сохранить прежний client_message_id до подтверждения snapshot либо определённого отказа до запуска; автоматический повтор с новым ID запрещён.
4. В первом прогоне исполнителя один прежний тест ignored mode write получил qt_timeout вместо mode_not_applied. Ведущий адресно повторил сценарий 12 раз — все вернули mode_not_applied. Причина единичного отказа ещё проверяется; ослаблять смысл проверки ради зелёного набора нельзя.

Базовые 153 теста до интеграции независимо прошли за 9.473 с. Для итоговой приёмки нужны законченный diff, новые проверки агента/HTTP/Preferences/SPA и общий прогон. Реальный STE, провайдер, G-code Preview и повторное открытие 3MF остаются неподтверждёнными; установленный плагин не обновлялся.

Независимая offline-проба текущей связки выполнена ведущим: ScriptedLLM → настоящий ToolRegistry → SlicerAdapter с ModeApp из прежних тестов → set_setting(layer_height=0.12) → ответ LLM. Два вызова подменного LLM, фактическое значение fake-стека 0.12, состояние idle, история user/assistant и события tool_started/tool_finished; load_model/assistant_status не передаются LLM. Использованы только подменные app/LLM на текущем потоке: это не проверка worker/Qt, HTTP, провайдера или установленного STE.
