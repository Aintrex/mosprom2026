## Что работает в коде

**Extension/Preferences.** Сохранены register(app), AIAssistant(app) и shutdown приложения. Qt-меню LLM Settings читает/сохраняет URL, модель и ключ через тот же bridge.run; worker использует app.callLater, Qt выполняет прямо. Успех сохранения подтверждается перечитыванием. При ошибке/игнорировании/таймауте кеш неподтверждён до reload, автоматического отката/повтора нет. Пустой ввод ключа сохраняет прежний; явный флажок удаляет. Поле пароля не заполняется сохранённым ключом. В браузер не передаются значения Preferences; сообщения/события редактируются, исключения/журнал содержат безопасный текст и тип ошибки.

**Клиент/агент.** Stdlib Chat Completions с проверкой TLS и без переноса Authorization по redirect. Function schemas берутся из единственного ToolRegistry; ответы role=tool используют tool_call_id. Формат сверялся с [официальным справочником Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); JSON-аргументы дополнительно проверяются локально. load_model(path) и scaffold assistant_status исключены из LLM. Диагностический MCP-импорт сохранён; для чата модель пока загружается вручную/через MCP. Вопрос о возможностях из временной кнопки допускает только чтения, даже если модель предложит мутацию. Для произвольных формулировок запрет скрытых изменений также задан промптом; семантического классификатора намерения не добавляли.

Один активный turn для всей сцены. Бюджеты: 8 обращений LLM, 16 инструментов, 120 секунд, отдельная сеть до 30 секунд с учётом остатка. Ответ ограничен 1 MiB; JSON nonfinite/неполный/неверный ответ не исполняется. Неправильные инструменты/аргументы отклоняются до API. После фактически начатой мутации с ошибкой, включая qt_timeout, остальные инструменты не выполняются; явные tool_not_executed сохраняются вместе с фактическим частичным результатом. Нет fallback/автоповтора. Ошибки завершают processing. При shutdown закрывается service до adapter; поздние ответы не запускают инструменты и не меняют завершённое состояние.

**HTTP/история.** Сохранены create_server, dispatch, /mcp, /api/health и legacy /api/message (последний — отдельное демо, новый SPA его не использует). tools/call без id не исполняется. Новые маршруты: status, создание/чтение sessions, сообщения с 202, корневой /api/events?session_id=&after=. Host/Origin ограничены собственным loopback-портом, сохранены Content-Type, 64 KiB JSON, 12000 символов текста, socket timeout 15 секунд, whitelist static, CSP/nosniff/no-store. Новый REST использует error:{code,message}.

Идемпотентность — по client_message_id и всему принятому trim-тексту/attachment_ids; дубль возвращает прежнее принятие, другое тело — 409. История — до 12 целых LLM-блоков, 200 видимых сообщений, 1000 событий/100 на страницу; 32 диалога, 512 принятых ID на диалог. Snapshot/курсор атомарны, 410 требует восстановления. При перезапуске процесса история исчезает, изменения автоматически не повторяются.

**Временный SPA.** Маршруты и поля приведены к API_CONTRACT, секретная форма удалена, configured не называется подключением. Восстанавливаются user/assistant и tool-карточки по event_id; разные turn различаются по turn_id + tool_call_id. Один polling, пагинация/backoff, восстановление после 410, прежний client_message_id/тело при обрыве/5xx. Показаны реальные результаты/отказы через textContent.

**Снимки нарезки.** valid/error/observed_at сохраняются из native-tool ответа; completed не равен актуальному результату. Уже прочитанный result сохраняется после актуального status того же slice и очищается при другом slice/устаревании. Изменение через агента публикует инвалидацию кеша. Результат имеет тот же суммарный material:{length_mm,weight_g}, что MCP. Никаких собственных расчётов времени, engine-данных или G-code нет.

## Ограничения и ручная приёмка

- Native не запускался: не подтверждены фактическая загрузка новой Extension, Qt-диалог, сохранение Preferences между перезапусками, реальная сеть/tool calling и полный сценарий UI. Ручная приёмка ТЗ 03/04/05/06/07 остаётся открытой; предыдущие ТЗ 01/02 не переобъявляются новой приёмкой.
- **Фонового наблюдения engine нет.** slice — последний результат start/status/result tools, явно подписанный в UI. После восьми быстрых LLM-опросов turn может закончиться раньше engine; это не ошибка/завершение native-job. Нужен новый явный запрос статуса/результата или MCP. Ручное изменение вне агента выясняется следующим tool-чтением, а не немедленно отражается в кеше сессии.
- Таймаут ограничивает ожидание caller; DNS/SSL/ОС могут завершить underlying transport позже. Один незавершённый daemon-запрос не размножается: новый вызов отклоняется request_busy до его выхода, late-ответ не принимается. Принудительного убийства сетевого потока нет.
- История/идемпотентность живут только в текущем процессе; постоянного журнала нет. localStorage используется для session/pending и не содержит ключа. Preferences — хранилище, требуемое ТЗ, без дополнительного vault.
- Native-приёмку после согласованного обновления всей установленной копии проводит ведущий с пользователем: сохранить проект; проверить Qt-настройки/перезапуск и вопрос без изменений; слой read/write/UI/restore; качество/материал и импорт отдельно; небольшая classic-модель, реальные status/result, штатный экспорт, Preview и повторное открытие 3MF. Команды ТЗ 01–07 в plugin/README.md сохранены. Реальные ключи вводит пользователь в Qt, в отчёт их не включать.
