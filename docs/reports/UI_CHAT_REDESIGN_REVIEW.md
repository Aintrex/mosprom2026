# Проверка нового интерфейса ведущим

## Повторный анализ после корзин диалогов — 25.10.2026

Коммитов, push, установки и новой реализации не выполнялось. Фронтендер завершил дополнение и остановился. Независимо повторены **46 JS-сценариев OK**, `node --check` и `git diff --check`. В настоящем браузере с автономной фикстурой проверены 1366×768 и 360×800: длинный непрерывный ввод, отдельная доступная отправка, 20 строк с корзинами, свёрнутые действия и видимые сообщения ошибок, карточки вложений и результатов. Горизонтального переполнения и ошибок консоли в этих сценариях нет. Проверки DELETE/отмены/неподтверждённого ответа/блокировок выполнены JS-набором; реальные архивы не удалялись.

Обнаружены два функциональных замечания уровня P2; это оставшиеся проблемы поведения списка, существовавшие и до переработки:

1. **Фоновое обновление сбрасывает клавиатурный фокус.** `app.js:116` полностью пересоздаёт строки при каждом `loadSessions`, в том числе из таймера `app.js:1098` примерно каждые 10 секунд. В браузере фокус был на корзине первого диалога, после очередного обновления `document.activeElement` стал `BODY`, без действий пользователя. Работа с Tab/Enter прерывается. Нужно сохранять строки при неизменных данных либо восстанавливать фокус по ID диалога и типу кнопки, не перехватывая фокус из другого поля. Добавить проверку фонового обновления списка при фокусе на названии/корзине.

2. **Выбор диалога молча стирает неотправленный черновик, включая повторный выбор текущего.** `openSession` (`app.js:158–166`) не исключает текущий ID, после GET очищает текст и выбранные файлы. В браузере набранный текст исчез и при переходе в другой диалог, и после клика по уже открытому. Минимально нужен no-op для текущего ID; для смены диалога — сохранение черновика либо явное предупреждение до удаления текста/вложений. Неподтверждённую отправку и прежние busy/upload guards сохранять. Это потеря локального черновика, не сохранённых сообщений.

Внешне основные требования выполнены. Критичных поломок в проверенном потоке не выявлено, но перед окончательной приёмкой стоит устранить эти два замечания. В рамках запроса проведён только анализ; исправления исполнителю не назначались. Автономные снимки сохранены локально под ignored `tmp/ui_redesign/lead_review_1366.png` и `lead_review_360.png`; фикстура содержит тестовые данные. Сервер остановлен, viewport сброшен, рабочая вкладка закрыта. STE, настоящая LLM, системный диалог подтверждения, реальные скачивания и мобильная экранная клавиатура этим анализом не проверены. Ошибка `describe_settings.keys` относится к аргументам инструмента и этим UI-изменением не исправляется.
