## Реализация

`agent/service.py`: один ленивый daemon-worker процесса, Event для wake/close, максимум две active-записи (slice/export). Только подтверждённые ID успешных start_slicing/export_gcode/save_project_3mf агента, привязанные к session_id. Примерно раз в1с читает прежние ToolRegistry→adapter→QtBridge status/result вне ServiceLock. Не сканирует историю/все сессии при polling, не читает приватные backend/Exports и не меняет native pipelines/guard/бюджеты/writers. После idle/ошибки/лимита LLM продолжает наблюдение **без новых LLM-запросов**, лимиты8/16/120 прежние. Сам не запускает/не повторяет slicing/export и не строит автоматическую цепочку slice→export. Прямой MCP/ручной UI/исторические IDs не становятся собственными операциями.

Completed/valid slice требует прежнего get_slicing_result с оценками STE; готовый собственный export проходит прежний2C resolver/DownloadRegistry вне lock. Поколение меняется **до** native-мутации, чтения приостанавливаются; после Qt и регистрации файла повторно проверяются closed/owner/ID/поколение. Поздний ответ не заменяет новую операцию/владельца и не оживляет known stale. Export tools не инвалидируют живой slice. Upload/attachments/download HTTP и единый реестр сохранены.

Прежние slice_progress/slice_finished/artifact_ready сохранены; observer не подделывает tool_started/tool_finished. Добавлены **один** последний snapshot.export (null до своего запуска) и export_progress одинаковой формы: export_id/slice_id/kind/state/progress/valid/error/observed_at/observation; kind=project/gcode. Нет local_directory/path/identity/байтов, pending не является artifact. Готовые files остаются в artifacts. Одинаковые статусы/артефакты дедуплицируются; observed_at означает изменение опубликованного снимка, не heartbeat каждого poll.

observation:{state:watching/finished/stopped,error:null|{code,message}} отделён от native state. watching — чтение продолжается; finished — terminal-наблюдение/результат, включая native failed/stale; stopped+observation_interrupted — чтение прекращено с неизвестным исходом engine. **Ошибка readback не является engine fail/cancel.** После4 последовательных ошибок с backoff1/2/4с запись снимается, последнее native state сохраняется с понятной ошибкой. Terminal-записи не опрашиваются бесконечно. Close ставит stop/wake и снимает ownership без join ожидающего Qt-worker на Qt. Принятый in-flight read может вернуться, но поздняя публикация/дальнейшие циклы отсекаются; engine/файлы не отменяются.

`web/app.js/index.html`: две простые строки slice/export с оценками из подтверждённого result и объяснением watching/stopped. Snapshot/refresh/410 восстанавливают оба статуса и download-карточки; нет POST/LLM из автообновления и редизайна. capabilities.background_slice_events=true только в plugin с native bridge, dev=false; это возможность собственных наблюдений, не готовность engine/лицензии. Обновлены API_CONTRACT/FRONTEND_INTEGRATION и короткие README. Native/slicer/downloads/HTTP-код этим2D не переписывался; PLAN/COORDINATION и инструкция/helper ведущего не менялись.

## Исправления по ревью

Terminal-final требует ok=true и подтверждённого результата. Ранний get_slicing_result с slice_not_ready либо transient qt_timeout **сохраняет живое наблюдение**. Явный slice_result_stale останавливает его с invalidated/finished; поздний read не восстанавливает valid. Сквозной тест: свой running → result/not_ready → LLM idle → transient result-read timeout → native finish → observer completed/result без нового LLM.

Достоверные предварительные busy-отказы — точный whitelist: slicing_busy/export_busy/selection_busy/model_load_busy/model_operation_busy/arrangement_busy/switch_in_progress. Подтверждены guard-ветками текущих adapter.py/exports.py/transforms.py/arrangement.py до изменения сцены/запуска writer. Они сохраняют полезный observer с новым поколением, не означают остановку engine. Адресный set_print_mode из worker при занятом guard реально возвращает switch_in_progress: classic/число запусков прежние, observer доходит до completed. Невыполненный из-за валидации tool наблюдение не прекращает. Неопределённые/частичные ошибки мутации явно прерывают observer и делают кеш stale, без молчаливой потери состояния.
