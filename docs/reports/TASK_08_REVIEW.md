**Дополнение после исходного ревью: открытое исправление.** При последующем чтении CLIParserBackend обнаружено, что общий `slicing.backend_busy` напрямую обращается к `_generate_basement_job`, которого этот backend не объявляет. Режим cylindrical использует именно CLIParserBackend; его собственная подготовка включает `_process_cli_job`. Следовательно, мутации 08 в idle cylindrical могут вернуть slicer_error. Исполнителю передано точечное исправление guard по подтверждённым layout и регрессионная проверка CLI без basement/с занятым process_cli. До отдельного результата это замечание остаётся открытым; 197 успешных проверок его не покрывали. Исходное заключение выше относится к первоначально просмотренному объёму.

**Замечание CLI исправлено и проверено отдельно:** guard явно различает подтверждённые backend ID/layout, для CLI проверяет `_process_cli_job` и ещё живой Glicer вместо отсутствующего basement; неизвестный layout отклоняется. Ведущий просмотрел diff и независимо повторил **17 проверок transforms, OK, 0.572 с**, включая idle cylindrical без basement, занятые jobs/process и отказ неизвестному backend. Новый общий прогон с этим изменением выполняется при итоговой приёмке 09; это исправление не добавляет 5D-нарезку.

Проверены единый ModelRegistry/ToolRegistry, строгие вложенные аргументы, классификация четырёх мутаций для агента, выполнение native Operations на Qt, удержание общего guard до подтверждения, мировые матрицы/origin/габариты и фактическое удаление.
