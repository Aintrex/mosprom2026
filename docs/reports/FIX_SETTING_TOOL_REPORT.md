# Исправление диагностики set_setting из чата

24.10.2026. Приоритетный реальный дефект по трём скриншотам пользователя. COORDINATION прочитана, изображения рассмотрены только как данные. Чтение layer_height=0.1/метаданных и импорт модели подтверждены скриншотами; изменение до0.12 не подтверждено. **Точный неверный payload set_setting неизвестен.** UI «Аргументы:null» был начальным значением renderer при tool_finished без tool_started; это не доказательство, что модель отправила raw null. Возможные string/лишнее поле/missing scope/не-JSON воспроизведены как отдельные случаи, ни один не объявлен установленной причиной пользовательского отказа.

## Изменение

- `agent/service.py`: parse/validate выделены в _validated_arguments **до** tool_started/_prepare_tool/tools.call. Только доказанный отказ этой стадии получает error.stage=validation/executed=false. Для setting-tools используется конкретное безопасное сообщение прежнего validator (ожидаемые поля/тип/обязательный scope), без raw значений. Непредвиденный ValueError после допуска к выполнению больше не маскируется как invalid_tool_arguments: execution_error → остановка мутаций, исход мог быть неизвестен.
- `agent/tools.py`: error.expected берётся из прежней общей schema, arguments_summary содержит лишь format, field_types известных полей, missing_fields и unknown_fields_count. Последнее считает имена вне общей schema, не условную допустимость extruder_id при global; эту причину определяет строгий validator. Нет raw JSON/значений/неизвестных имён/путей/новых логов или endpoints. Описания get/set schema и set_setting уточняют: global — ровно key/scope/value без extruder_id даже null, layer_height — JSON-число в мм, например0.12, не строка. Bool/enum имеют прежние собственные типы.
- System-инструкции допускают исправленный моделью вызов **только** при stage=validation/executed=false в прежних8/16/120 пределах. Аргументы не исправляются кодом: нет подстановки scope/парсинга0.12 из пользовательского текста/ослабления validators. После запущенной/неизвестной мутации, execution_error или timeout повтор запрещён, чтение/UI для выяснения состояния.
- `web/app.js`: для marked pre-validation без started — «Отклонено до запуска» и текст безопасной причины/summary/schema. Исторический finished без started/доказательства — «Аргументы не опубликованы; запуск API не подтверждён», а не ложный null или доказанная отмена. Реальные аргументы показываются лишь из started. Refresh/410, парные turn/call ID и textContent сохранены; UI сам не повторяет POST/tool.
- Добавлен `tests/test_setting_tool_rejection.py`, два JS-сценария; обновлены API_CONTRACT/FRONTEND_INTEGRATION. Реестр/валидация MCP(-32602)/QtBridge/native guards/engine/writers/2Dworker/лимиты сохранены. Frozen296/manifest и инструкция/helper ведущего не менялись. AppData/установка/ключи/реальный LLM/STE/принтер/новые чаты не использовались. Git-мутации/публикацию делает только ведущий по отдельному разрешению пользователя.
