# Архитектура и контракты

```text
SPA в браузере -> HTTP на 127.0.0.1 -> AgentService -> Chat Completions
                                      |
                                      v
                               общий ToolRegistry
                                      |
                                      v
                          SlicerAdapter -> app.callLater -> Qt/API

HTTP /mcp -> JSON-RPC dispatch -> тот же ToolRegistry
```

## Реализовано в каркасе

- Регистрация Extension, пункт меню, старт сервера на свободном loopback-порту и открытие браузера; shutdown при выходе приложения.
- Статические HTML/CSS/JS без npm и серверного рендеринга.
- `GET /api/health`: `{"status":"ok","mode":"scaffold"}`.
- `POST /api/message`: `{"text":"..."}` -> `{"reply":"...","events":[],"mode":"scaffold"}`. Ответ локальный демонстрационный. История пока существует только в DOM текущей вкладки.
- `POST /mcp`: минимальные `initialize`, `tools/list`, `tools/call`, JSON-RPC ошибки и уведомления без ответа. Единственный инструмент `assistant_status` описывает состояние каркаса.
- JSON-only POST, ограничение размера, проверка Host/Origin, статические файлы по фиксированному списку, вывод текста в UI через `textContent`.

Это основа для разработки, не готовый MCP-сервер со всеми транспортными возможностями. Версия протокола initialize сейчас фиксирована `2024-11-05`; согласование версии и совместимость клиента проверить отдельно. Экспорт, фактический слайсинг и подключение к LLM отсутствуют. Методы-заготовки явно вызывают `NotImplementedError`.

## Очередь реализации

1. Проверить Extension в реальной сборке. Найти реальные ключи режима в `resources/definitions` и примеры API во встроенных плагинах.
2. Реализовать мост задач: HTTP worker создаёт `job_id`, `app.callLater` выполняет работу; результаты и ошибки возвращаются через очередь/события. Не ждать HTTP в Qt-потоке. Слайсинг и загрузка моделей асинхронны: завершение определять по сигналам, не по возврату функции.
3. Добавить адаптеры чтения/изменения настроек и сцены. Чтение API тоже выполнять в главном потоке.
4. Добавить Preferences и форму конфигурации URL/model/key; чтение и запись Preferences также через Qt. В SPA возвращать только признак наличия ключа.
5. В `llm.py` реализовать `urllib.request`, timeout, ошибки API; в `service.py` цикл assistant -> tool_calls -> tool results -> assistant с лимитом шагов и последовательными изменениями одного проекта.
6. Реализовать загрузку файлов (типы, размеры, безопасное имя, внутренний ID). Изображения отправлять в LLM через base64 `image_url`; модели передавать через инструменты слайсера. Не объявлять загрузку успешной до фактического появления объекта.
7. Добавить очередь событий и polling, показывать реальные tool calls, ошибки и прогресс.
8. Подключить писатели GCodeWriter/3MFWriter по образцам конкретной сборки. Экспортировать только результат завершённого слайсинга и показывать фактический путь/ссылку на результат.

## Предлагаемые контракты для следующего этапа

Общий результат инструмента: `{"ok": true, "data": {...}}` либо `{"ok": false, "error": {"code": "...", "message": "..."}}`. MCP оборачивает его в `content` и выставляет `isError`; LLM получает тот же фактический результат. Не сообщать успех по одному лишь плану агента.

Событие: `{"id": 1, "session_id": "...", "type": "tool_started", "data": {...}}`.
Предлагаемые типы: `assistant_message`, `tool_started`, `tool_finished`, `slice_progress`, `slice_finished`, `error`.
Предлагаемый polling: `GET /api/events?session_id=...&after=1`. Эти маршруты пока не реализованы.

## Совместимость

Не использовать f-strings, dataclasses, annotations переменных, `pathlib` API новых версий, `asyncio.run`, `ThreadingHTTPServer` и официальный MCP SDK. Базовый сервер использует stdlib; дополнительные runtime-зависимости проверять по выданному Python. Синтаксическая проверка парсером Python 3.5 не заменяет запуск в дистрибутиве.

Ключи, полные исходные страницы с доступами и файлы активации не переносить в репозиторий. Локальные материалы исследования уже лежат в `tmp/`, этот каталог игнорируется Git.
